# SIMPL-31153: A Trusted Governance Authority forwards and receives resource-description details via API
- Status: FOR SC TO RESPOND
- Type: Story
- Created: 2026-08-04, updated: 2026-10-22
- Source: https://jira.simplprogramme.eu/browse/SIMPL-31153 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority,\
**I want** to receive a resource-detail request from consumer, forward it to the relevant Trustor Governance Authority, and receive the response via API,\
**So that** I can provide it to the Consumer.

Note

This ticket also covers the scope of [https://jira.simplprogramme.eu/browse/SIMPL-31149]

# Acceptance criteria

## AC1 - Receive and forward the detail request

**Given** I, the Governance Authority, am trusted by a Trustor Governance Authority\
**And** a resource description belonging to a catalogue of that Trustor Governance Authority\
**When** I receive from a Consumer a request for the details of that resource description\
**Then** I forward the request to the Trustor Governance Authority

## AC2 - Return the Trustor response to the Consumer flow

**Given** I, the Trusted Governance Authority, have received from a Consumer a request for the details of a resource description in a federated catalogue of a Trustor Governance Authority\
**And** I have forwarded the request to the Trustor Governance Authority\
**When** the Trustor Governance Authority returns the details of the requested resource description, -along with the associated schema-\
**Then** Simpl-Open forwards the resource description details -and associated schema- to the Consumer

## AC3 - Propagate a Trustor error

**Given** I, the Trusted Governance Authority, have received from a Consumer a request for the details of a resource description in a federated catalogue of a Trustor Governance Authority\
**And** I have forwarded the request to the Trustor Governance Authority\
**When** the Trustor Governance Authority returns an error or no resource description\
**Then** Simpl-Open forwards the error or not-found response to the Consumer

# Technical description

The Trusted Governance Authority's local catalogue-query-mapper-adapter must implement the complete adapter-side flow between xfsc-advsearch-be and the Trustor Governance Authority.

**When** xfsc-advsearch-be sends a federated resource-detail request, the adapter, acting in the Trusted Governance Authority role, must:\
* accept the resource identifier, Consumer identity attributes, and correlation information from xfsc-advsearch-be;\
* resolve the relevant Trustor Governance Authority and forward the request to the Trustor's catalogue-query-mapper-adapter using the established mutual TLS authentication;\
* correlate the Trustor response with the forwarded request;\
* return the resource description {-}and schema{-}, or the defined error, to xfsc-advsearch-be; and\
* preserve the resource identifier and response status needed by the Consumer-facing endpoint.

xfsc-advsearch-be must then provide the initiating Consumer with the resource description through the existing resource-detail response representation, {-}with the schema available as part of the federated response path{-}. This applies only to the federated branch; requests for resources in the own catalogue continue to use the existing direct catalogue path.

The API definition must cover both the xfsc-advsearch-be{-}to-Trusted-adapter request and response and the Trusted-adapter-to-Trustor-adapter request and response. It must define the successful resource-description{-}{-}and-schema payload{-}, not-found response, policy-denied response, authentication failure, timeout, and downstream error. Errors received from the Trustor Governance Authority must be translated consistently without exposing internal federation details or protected data.

# Technical design

The implementation of [SIMPL-31153](https://jira.simplprogramme.eu/browse/SIMPL-31153) must implement the API contracts defined in the API Definition section below for both the Trusted-side inbound request and the adapter-to-adapter forwarding and response flow.\
* Add the Trusted-side inbound operation receiving federated resource-detail requests from xfsc-advsearch-be.\
* Add the Trusted-side forwarding operation to the Trustor adapter.\
* Return the adapter response to the existing xfsc-advsearch-be resource-detail endpoint.\
* Preserve the existing Consumer-facing response format where possible.\
* Keep the own-catalogue lookup path unchanged.\
* Add end-to-end tests covering a successful federated lookup and propagated Trustor-side errors.
