# SIMPL-29292: [UI] Provider use quick search with quality filter (minimum score and classification)
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2026-06-29, updated: 2026-10-15
- Source: https://jira.simplprogramme.eu/browse/SIMPL-29292 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Participant,\
**I want** the Quick Search UI to provide filter options for minimum score and minimum classification,\
**So that** I can quickly narrow results to resource descriptions that meet my expected quality level.

## Acceptance Criteria

### AC1

**Given** I am authenticated and can access Catalogue Client UI\
**When** I open the Quick Search Tab\
**Then** I can see optional filter fields for minimum score and minimum classification.

### AC2

**Given** I enter a minimum score in Quick Search tab\
**When** I execute search\
**Then** only resource descriptions with overallScore greater than or equal to the minimum score are returned.

### AC3

**Given** I select a minimum classification in Quick Search\
**When** I execute search\
**Then** only resource descriptions with overallCategory equal to or better than the selected minimum classification are returned.

*Note on classification hierarchy:*\
Classification labels (e.g. "Poor", "Sufficient", "Good") are *dynamic,* they are defined and named by the Governance Authority as part of the active Metadata Quality Profile (MQP) and are not hardcoded in the system (see functional description: "The Governance Authority can define a metadata quality classification to label the level of quality", and technical description: "The Advanced Search UI dynamically retrieves fields from the Metadata Quality Profile to provide Consumers with intuitive quality filters").

The ordering used to evaluate "equal to or better than" is derived from the *score ranges* assigned to each classification in the active MQP. A classification is considered *better* than another if its associated score range has a strictly higher lower bound. For example, if the active MQP defines:\
- "Poor": 0–40 %\
- "Sufficient": 40–70 %\
- "Good": 70–100 %

then selecting "Sufficient" as the minimum returns resource descriptions classified as "Sufficient" or "Good", because those classifications correspond to score ranges with a lower bound ≥ 40 %.

### AC4

**Given** I set both minimum score and minimum classification\
**When** I execute search\
**Then** only resource descriptions matching both filters are returned.

### AC5

**Given** no minimum score and no minimum classification are set\
**When** I execute search\
**Then** Quick Search behavior remains unchanged and quality filters are not applied.

### -AC6-

-Given a resource description has no score and classification-\
-When one or more quality filters are active-\
-Then that resource description is excluded from the filtered result set-\
-And search execution continues without failure.-

### -AC7-

-Given an invalid score format or classification format-\
-When I execute search-\
-Then the UI shows a clear validation message-\
-And prevents submitting invalid filter values.-

## Technical Details\
* Add two optional UI controls to Quick Search: minimum score and minimum classification.\
* Map the two filter values to the Quick Search request model.\
* Apply both filters together with existing Quick Search criteria.\
* Treat empty filter fields as not set and do not send restrictive values.\
* Add input validation and inline error messages for invalid score/classification inputs.\
* The filter options are added to the quick search tab and not to the bar in the header
