# SIMPL-31142: [UI] A Consumer consults the overview of resource descriptions returned from federated catalogues by a search request via UI
- Status: FOR SC TO RESPOND
- Type: Story
- Created: 2026-08-04, updated: 2026-10-28
- Source: https://jira.simplprogramme.eu/browse/SIMPL-31142 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Consumer\
**I want** to consult an overview of the search results from the federated data space catalogues via UI\
**So that** I can decide on further actions.

Technical Design\
# Enhance the existing Search UI to display search results in a tab-based layout.\
# Upon clicking the Search button, a search request is sent to the xfsc-adv-search component (SIMPL-33462, SIMPL-33465).\
# The search results returned by xfsc-adv-search are grouped by federated catalogue.\
# The UI dynamically creates one tab for each federated catalogue selected in the search request.\
# Each tab displays only the resource descriptions returned by the corresponding federated catalogue.\
# Users can navigate across tabs to review and compare the results coming from the different federated catalogues.\
# For each resource description, the main properties are displayed according to the existing search results view.

Quick Search\
* Local Search → invoke the local catalogue search API (catalogue-client-be GET /selfDescriptions) using the search term provided by the user.\
* Federated Search → invoke the federated search API (SIMPL-33462) using the same search term and the selected federated catalogues.\
* Result Visualization → create dedicated tabs for the local catalogue and each federated catalogue containing matching resource descriptions.

Advanced Search\
* Local Search → invoke the local catalogue search API (catalogue-client-be POST /selfDescriptions) using the selected federated catalogues and the filters related to resource schema selected.\
* Federated Search → invoke the federated search API (SIMPL-33465) using the selected federated catalogues and the filters related to federated search schema.\
* Result Visualization → create dedicated tabs for the local catalogue and each federated catalogue containing matching resource descriptions.

Acceptance criteria

Scenario 1 - one response, grouped per catalogue

**Given** a Consumer that had submitted a search request\
**When** I, the Governance Authority, have obtained the results by performing the search on my own catalogues (if relevant)\
**And** I have obtained the search results from each involved Trustor Governance Authority\
**Then** Simpl-Open returns the results to the initiating Consumer in a single response\
**And** the results remain grouped per catalogue, each group identifying its catalogue and the Governance Authority that provided it\
**And** results from different catalogues are not merged into one combined list

Scenario 2 - paging per catalogue

**Given** a search result grouped per catalogue\
**When** the Consumer requests a further page of results for one catalogue\
**Then** Simpl-Open provides paging information for each catalogue group independently, as it does for a search on an own catalogue\
**And** paging one group leaves the other groups unaffected

Scenario 3 - a Trustor Governance Authority returns nothing

**Given** a search request that includes one or more federated catalogues\
**When** a Trustor Governance Authority cannot authenticate the request, or returns no results\
**Then** Simpl-Open returns an empty group for that catalogue\
**And** the groups of all other catalogues are returned unaffected

Scenario 4 - metadata quality

**Given** a search result containing groups from own and from federated catalogues\
**When** the results are returned to the Consumer\
**Then** the metadata quality score is included only for groups from own catalogues\
**And** it is omitted for groups from catalogues of a Trustor Governance Authority
