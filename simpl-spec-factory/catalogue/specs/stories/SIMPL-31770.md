# SIMPL-31770: [BE] A Consumer consults the full contents of a resource description returned from a federated catalogue by a search request via API

## Description and acceptance criteria

**As a** Consumer,\
**I want** to consult the details (all properties) of a resource description found by a search from a federated catalogue of a data space via API,\
**So that** I can decide on further actions and can start the contract negotiation.

# Acceptance criteria

## AC1 – Consult federated resource details via API

**Given** I am a Consumer that has requested the details of a Resource Description from a federated catalogue of a dataspace\
**When** my Governance Authority successfully retrieves the details of the requested Resource Description\
**Then** all published properties of the requested Resource Description are included in the returned result\
**And** the applicable schema associated with the Resource Description is included in the returned result -\
**And** the API returns HTTP 200 OK.

## AC4 – Downstream service failure

**Given** I am a Consumer that has requested the details of a Resource Description from a federated catalogue of a dataspace\
**When** the federated detail request cannot be completed because of a downstream service failure\
**Then** the request fails\
**And** the API returns the corresponding error response according to the defined API contract.

## AC5 – Invalid request

**Given** I am a Consumer that has requested the details of a Resource Description from a federated catalogue of a dataspace\
**When** the request contains missing or invalid mandatory parameters\
**Then** the request is rejected\
**And** the API returns HTTP 400 Bad Request.

# Technical description

The existing xfsc-advsearch-be resource-detail API must allow a Consumer to retrieve the full contents of a resource description returned by a federated search.

For a federated resource, the API must:\
* accept the resource identifier returned by the federated search;\
* request the details through the local Trusted Governance Authority flow;\
* preserve the existing resource-detail representation, return all published properties, and carry the applicable schema returned by the federated flow;\
* return defined not-found, forbidden, timeout, and downstream-error responses; and\
* keep the own-catalogue lookup behavior unchanged.

The participant-facing API change is an extension of the existing resource-detail capability, not a new standalone API. The Governance Authority forwarding, identity mapping, policy evaluation, Trustor catalogue lookup, and Schema Manager lookup are implemented by [SIMPL-31150](https://jira.simplprogramme.eu/browse/SIMPL-31150) and [SIMPL-31153](https://jira.simplprogramme.eu/browse/SIMPL-31153).

# Technical design\
* Extend the existing xfsc-advsearch-be GET /selfDescriptions/{id} flow to support federated resource identifiers.\
* Invoke the local Trusted Governance Authority flow for federated resources and retain the direct own-catalogue path.\
* Return the complete resource-description representation to the Consumer through the API, with the applicable schema propagated by the federated response path.\
* Preserve the existing API contract for own-catalogue resources.\
* Add API tests for successful federated retrieval, not-found, forbidden, timeout, and downstream-error cases.
