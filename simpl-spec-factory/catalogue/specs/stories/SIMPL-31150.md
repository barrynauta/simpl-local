# SIMPL-31150: [API Implementation] A Governance Authority handles request for the details of a resource description from a Trusted Governance Authority via API
- Status: DevTeam PBI In Progress
- Type: Story
- Created: 2026-08-04, updated: 2026-10-23
- Source: https://jira.simplprogramme.eu/browse/SIMPL-31150 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority,\
**I want** to handle a request for the details of a resource description from a Trusted Governance Authority,\
**So that** the Trusted Governance Authority can provide it to the Consumer.

Note

This US also covers the scope of [https://jira.simplprogramme.eu/browse/SIMPL-31152] and [https://jira.simplprogramme.eu/browse/SIMPL-31151], as it is part of one API and the parts are hard to test in isolation.

# Acceptance criteria

## AC1 - Handle an authorised request

**Given** the Governance Authority, receives a request for the details of a resource description from a Trusted Governance Authority\
**And** the request includes the identity attributes of the Consumer at the origin of the request\
**And** the requesting Trusted Governance Authority is authenticated and its federation with this Governance Authority is still enabled\
**When** the identity attributes included in the request are mapped to the identity attributes as defined by the Trustor Governance Authority\
**And** these mapped attributes comply with the discovery access policies of the resource description\
**Then** Simpl-Open provides the details of the resource description to the Trusted Governance Authority that requested it.

## AC2 - Reject an unauthorised request

**Given** the Governance Authority receives a request for the details of a resource description from an unauthenticated or no-longer-trusted Governance Authority\
Or the request is received without the identity attributes of the Consumer at the origin of the request\
**When** I process the request\
**Then** Simpl-Open refuses the request and does not return the protected resource description.

## AC3 - Reject on discovery access policies

**Given** the Governance Authority receives a request for the details of a resource description from a Trusted Governance Authority\
**And** the request includes the identity attributes of the Consumer at the origin of the request\
**And** the requesting Trusted Governance Authority is authenticated and its federation with this Governance Authority is still enabled\
**When** the identity attributes included in the request are mapped to the identity attributes as defined by the Trustor Governance Authority\
**And** these mapped attributes do not comply with the discovery access policies of the resource description\
**Then** Simpl-Open refuses the request and does not return the protected resource description.

## AC4 - Return the authorised resource description

**Given** the request is authorised and the resource description exists in the local catalogue\
**When** the Trustor Governance Authority processes the request\
**Then** Simpl-Open returns the resource description and correlation information to the requesting Trusted Governance Authority.

# Resource-detail flow

# Technical description

The Trustor Governance Authority's `catalogue-query-mapper-adapter` must expose a new authenticated inbound operation for resource-detail requests from a Trusted Governance Authority and complete the full Trustor-side request/response flow.

The operation must:\
* authenticate the calling Trusted Governance Authority using the established mutual TLS mechanism and verify that its federation is still enabled when the details request is handled; this authenticates the Governance Authority, while the mapped Consumer attributes are used for discovery-policy evaluation;\
* accept the resource identifier, the originating Consumer context, the Consumer's public identity attributes, and correlation information;\
* invoke the R24 identity-attribute mapping for the relationship with the requesting Trusted Governance Authority, as defined by [SIMPL-30844](https://jira.simplprogramme.eu/browse/SIMPL-30844);\
* query the local `catalogue-be` only after the request is authorised;\
* -retrieve the applicable resource-description schema from Schema Manager;-\
* construct the agreed resource-description response with schema and correlation information; and\
* return the resource description {-}and schema{-}, or a defined error response, to the requesting Trusted Governance Authority.

The endpoint must not expose the resource description when the resource does not exist, the caller is not authenticated or its federation is no longer enabled, the identity mapping is unavailable, or the mapped attributes fail the discovery access policy. The API definition must document the request, response, authorisation, and error contracts.

# Technical design

The implementation of [SIMPL-31150](https://jira.simplprogramme.eu/browse/SIMPL-31150) must implement the API contract defined in the API Definition section below and keep the existing participant-scoped resource-description endpoint contract unchanged.\
* Add the Trustor-side inbound resource-detail operation to ``catalogue-query-mapper-adapter``.\
* Reuse the existing federation authentication and identity-attribute mapping mechanisms as described by Aruba;\
see steps 5 - 11 using this [IAA interface](https://code.europa.eu/simpl/simpl-open/development/iaa/common/-/blob/v2.15.0/simpl-api-iaa/src/main/resources/static/openapi/tier-1/securityattributesprovider-tier1-v2.yaml?ref_type=tags)\
look up in the resultset of mapping where these passed identity attributes matches the code of remoteAuthorityAttribute and replace them with the code of localAuthorityAttribute. In addition add Code of any additionalIdentityAttributes in the result set.\
* Add the policy-evaluation step before the local catalogue lookup.\
* Query the local catalogue for the requested resource description.\
* Define and implement the successful and error response schemas for the Trustor-side operation.\
* -Retrieve the applicable schema from Schema Manager after the local catalogue lookup.-\
* Return the resource description, {-}schema{-}, correlation information, and required metadata to the requesting Trusted adapter.\
* Add positive, not-found, unauthorised, missing-attributes, policy-denied, federation-revoked-after-discovery, and downstream-error test cases.
