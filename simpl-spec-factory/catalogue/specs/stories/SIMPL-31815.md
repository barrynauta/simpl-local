# SIMPL-31815: GA defines federated Search Schema via API

## Description and acceptance criteria

**As a** Governance Authority\
**I want** to create via a API, a federated search schema by providing a comprehensive and structured definition, detailing its properties, data types, constraints, validation rules, and any relationships or dependencies.\
**So that** I can ensure Consumers of my data space can perform advanced search in catalogues of federated data spaces

Acceptance criteria:\
**Given** I am an authenticated Governance Authority user that has the GA_SCHEMA_ADMIN role,\
**When** I create a new schema using the endpoint POST /schemas with schemaType="SEARCH", a schema name, a title, and a shacl definition\
**And** no resourceType specified\
**And** the schema is valid\
**Then** Simpl shall respond with a 201 Created response from the API.

negative case:\
**Given** I am an authenticated Governance Authority user that has the GA_SCHEMA_ADMIN role,\
**When** I create a new schema using the endpoint POST /schemas with schemaType="SEARCH", a schema name, a title, and a shacl definition\
**And** a resourceType is specified\
**Then** Simpl shall respond with an error (400 Bad request) stating no resourceType allowed for federated search schema.I.

**Given** I am an authenticated Governance Authority user that has the GA_SCHEMA_ADMIN role,\
**And** there exists already another published federated search schema\
**When** I create a new schema using the endpoint POST /schemas with schemaType="SEARCH", a schema name, a title, and a shacl definition\
**And** no resourceType specified\
**Then** Simpl shall respond with an error (409 Conflict) stating There exists already another published search schema.
