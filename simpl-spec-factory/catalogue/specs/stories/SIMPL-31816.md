# SIMPL-31816: [UI] Trusted GA defines federated Search Schema via UI
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2026-08-17, updated: 2026-10-23
- Source: https://jira.simplprogramme.eu/browse/SIMPL-31816 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority\
**I want** to create via a UI, a federated search schema by providing a comprehensive and structured definition, detailing its properties, data types, constraints, validation rules, and any relationships or dependencies.\
**So that** I can ensure Consumers of my data space can perform advanced search in catalogues of federated data spaces

Acceptance criteria:

**Given** I am authenticated as a Governance Authority user, with a role authorising schema management\
**When** I create a federated search schema via UI\
**Then** Simpl shall allow me to provide the schema properties, their data types, constraints, validation rules and any relationships or dependencies for further validation and storage.

**Given** a federated search schema already exists\
**When** I attempt to create a second schema with schemaType = SEARCH\
**Then** Simpl-Open rejects the creation and reports that only one federated search schema may exist

Technical details:\
* modify Schema management API (see [API-Definition impl-30422l](https://jira.simplprogramme.eu/browse/SIMPL-30422) to introduce the new attribute schemaType to distinguish between RESOURCE for the current existing resource definition schemas and the new one SEARCH.\
* modify UI dialog to create, read, update or delete a schema. Support new introduced attribute schemaType to distinguish between RESOURCE for the current existing resource definition schemas and the new one SEARCH.\
* Take care: There is only one federated search schema! Ensure not more than one can be created
