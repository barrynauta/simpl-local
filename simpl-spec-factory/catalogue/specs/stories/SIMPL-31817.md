# SIMPL-31817: GA create new version of federated search schema via API

- Type: Story
- Created: 2026-08-17, updated: 2026-10-13
- Source: https://jira.simplprogramme.eu/browse/SIMPL-31817 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority\
**I want** to create via a API, a new version of a federated search schema by providing a comprehensive and structured definition, detailing its properties, data types, constraints, validation rules, and any relationships or dependencies.\
**So that** I can ensure Consumers of my data space can perform advanced search in catalogues of federated data spaces

Acceptance criteria:

Acceptance criteria:\
**Given** I am an authenticated Governance Authority user that has the `GA_SCHEMA_ADMIN` role,\
**When** I create a new version of a given federated search schema using the endpoint `POST /schemas/<schemaName>/versions` with `schemaType="SEARCH", a given schema name, a title, and a shacl definition`\
* `And` no resourceType specified\
* `And` the schema is valid\
**Then** Simpl shall respond with a `201 Created` response from the API.

negative case:\
**Given** I am an authenticated Governance Authority user that has the `GA_SCHEMA_ADMIN` role,\
**When** I create a new version of a given federated search schema using the endpoint `POST /schemas/<schemaName>/versions` with `schemaType="SEARCH", a given schema name, a title, and a shacl definition`\
* `And` a resourceType for instance "DATA" is specified\
**Then** Simpl shall respond with an error (`400 Bad Request`) stating no resourceType allowed for federated search schema.

**Given** I am an authenticated Governance Authority user that has the `GA_SCHEMA_ADMIN` role,\
**And** there is already another published federated search schema\
**When** I create a new version of a given federated search schema using the endpoint `POST /schemas/<schemaName>/versions` with `schemaType="SEARCH", a given schema name, a title, and a shacl definition`\
* `And` a resourceType for instance "DATA" is specified\
**Then** Simpl shall respond with an error (`409 Config`) stating there is already another published federated search schema.

Technical Design:\
This US is covered with the implementation of [SIMPL-33537](https://jira.simplprogramme.eu/browse/SIMPL-33537) and only for linkage to the epic.

Technical details:\
* modify version capability of Schema management API (see [API-Definition impl-30422l](https://jira.simplprogramme.eu/browse/SIMPL-30422)]. Distinguish the new introduced attribute schemaType: RESOURCE for exiting one, SEARCH for the new federated Search Schema.

* For schemaType="RESOURCE" the resourceType is mandatory. For schemaType="SEARCH" there is only one schema instance allowed and resourceType is not specified (null), as this schema is valid for all resource types (App, Infra, Data).

* Distinguish the new introduced attribute schemaType: Ressource for exiting one, SEARCH for the new federated Search Schema.\
* Take care: There can only be one federated search schema! Not more than one!\
* The other negative scenarios are in this ticket [SIMPL-13357](https://jira.simplprogramme.eu/browse/SIMPL-13357)
