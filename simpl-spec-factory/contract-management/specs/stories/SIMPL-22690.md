# SIMPL-22690: [Replaced] A Consumer accepts a usage contract offer via UI
- Status: DevTeam PBI blocked
- Type: Story
- Created: 2026-01-02, updated: 2026-10-20
- Source: https://jira.simplprogramme.eu/browse/SIMPL-22690 (collected 2026-10-29)

## Description and acceptance criteria

Why:\
To explicitly confirm that the Consumer agrees with the reviewed usage contract offer and wants to proceed.

What:\
**As a** Consumer who has already reviewed a usage contract offer from a Provider\
**I want** to accept the reviewed usage contract offer via the Consumer Contract Manager UI\
**So that** the contract establishment process can continue to the signing phase.

Acceptance Criteria

-*AC1 - Successful usage contract offer review*-\
* -*Given* that I am an authenticated Consumer-\
* -*-And-* I have successfully reviewed the human-readable usage contract offer-\
* -*And* the human-readable usage contract offer is displayed to the Consumer-\
* -*When* I explicitly select the “Accept” action in the Consumer Contract Manager UI-\
* -*Then* the acceptance message is passed to the dedicated Consumer's Connector endpoint for further processing-

*AC1 - Successful usage contract offer acceptance*

**Given** that I am an authenticated Consumer\
**And** the human-readable usage contract offer is displayed to the Consumer\
**When** I explicitly select the “Accept” action in the Consumer Contract Manager UI\
**Then** the Accept decision is submitted through Contract UI Backend\
**And** Contract UI Backend forwards the decision to Contract Backend using the API defined in SIMPL-28977\
**And** Contract Backend continues the backend integration flow towards Contract Orchestrator / EDC\
**And** the decision flow preserves contractNegotiationId and correlationId where available\
**And** the acceptance is logged with sufficient technical details.

*AC2 - Usage contract offer unavailable*\
**Given** I am authenticated as a Consumer\
**And** the human-readable usage contract offer is displayed to the Consumer\
**When** I attempt to accept the usage contract offer\
**And** the acceptance process fails\
**Then** an error response is returned\
**And** the contract negotiation remains active

*Technical Info*

The UI action is handled through the Contract UI Backend.

*Target flow:*

Contract UI Frontend -> Contract UI Backend -> Contract Backend -> Kafka -> Contract Orchestrator -> EDC

The frontend must not call Contract Backend directly.

For the Accept or Reject action, Contract UI Frontend invokes the corresponding Contract UI Backend operation. Contract UI Backend forwards the decision to Contract Backend using the API defined in SIMPL-28977.

Contract Backend is responsible for continuing the backend integration flow towards Contract Orchestrator and EDC.

The decision flow must preserve contractNegotiationId and correlationId where available.

*Security & Compliance:*\
* *Authentication:* Consumer authenticated before UI access\
* *Replay protection:* acceptance endpoint idempotent per contractNegotiationId\
* *Non-repudiation (business level):* acceptance decision recorded immutably in audit log
