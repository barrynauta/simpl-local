# SIMPL-19934: Provider signs the received contract previously signed by the Consumer
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-10-24, updated: 2026-10-26
- Source: https://jira.simplprogramme.eu/browse/SIMPL-19934 (collected 2026-10-29)

## Description and acceptance criteria

**Why**: The Provider must issue the final signed version of the usage contract so that both parties have a cryptographically verifiable, mutually binding agreement.

**What**:

**As a** Provider,\
**I want** to digitally countersign the usage contract that was first signed by the Consumer,\
**So that** the finalized contract is signed by both parties and can be returned to the Consumer as a legally valid agreement.

**Acceptance Criteria**:

*AC1 - Successful case - Contract signature*\
**Given** I am a Provider\
**And** I validated the usage contract signed by the Consumer, triggering the Provider Contract Manager to automatically start the signing process via the backend API\
**When** the Provider Contract Manager starts the signing process with the backend API\
**Then** the Provider Contract Manager involves the VC issuer and the the Digital signature service to produce the final contract signed by both parties\
**And** the system returns HTTP 200 (OK) with status "Finalized"\
**And** the system marks the contract negotiation state as "Finalized".

*AC2 - System error handling*\
**Given** I am a Provider\
**And** I validated the usage contract signed by the Consumer, triggering the Provider Contract Manager to automatically start the signing process via the backend API\
**When** the Provider Contract Manager starts the signing process with the backend API\
**And** a system error occurs at any step (e.g., VC Issuer Service error, Digital Signature Service error)\
**Then** the error is logged with technical details\
**And** the system returns HTTP status 500 (Internal Server Error) with an error reference

**Technical Info**:\
* The Provider signature is performed automatically by backend services (VC Issuer + Digital Signature Service). Human UI interaction is not required.\
* The Contract Manager completes the following steps to achieve the signing process:\
** the Contract Manager requests the VC Issuer Service to create an unsigned Signature VC\
** the Contract Manager invokes the Digital Signature Service to sign the Signature VC\
** the Digital Signature Service signs the VC and returns the signed Signature VC to the Contract Manager\
** the Contract Manager produces the final contract signed by both parties\
* HTTP Status Codes:\
**

```\
500: Internal Server Error - system errors\
```
