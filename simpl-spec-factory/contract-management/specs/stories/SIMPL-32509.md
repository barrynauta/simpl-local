# SIMPL-32509: [API] - API to verify existing usage contract
- Status: New Product Backlog Item
- Type: Story
- Created: 2026-09-03, updated: 2026-09-22
- Source: https://jira.simplprogramme.eu/browse/SIMPL-32509 (collected 2026-10-29)

## Description and acceptance criteria

New proposed: Replaces SIMPL-19824

**As a** Provider\
**I want** to verify if the Consumer already has an active usage contract for a selected resource description from the data space catalogue\
**So that** I can avoid initiating a second contract for the same Consumer and resource

AC1: A Provider verifies if the Consumer already has an active usage contract for a resource – positive case

**Given** an authenticated Consumer authorised to submit a usage contract offer request\
**And** the Consumer submits a usage contract offer request related to a resource description\
**And** the usage contract offer request is sent to the Provider\
**When** the Provider verifies if the Consumer already has an active usage contract for the resource\
**And** the Provider invokes the POST /resourceDescriptions/{resourceDescriptionId}/validateExistenceContract API\
**Then** I receive a 200 Ok response\
**And** the body of the response contains\
resourceDescriptionId (UUID)\
ConsumerId (UUID)\
Exists (boolean)

AC2: A Provider verifies if the Consumer already has an active usage contract for a resource – error case (resourceDescriptionId not found)

**Given** an authenticated Consumer authorised to submit a usage contract offer request\
**And** the Consumer submits a usage contract offer request related to a resource description\
**And** the usage contract offer request is sent to the Provider\
**And** the resourceDescriptionId does not exist\
**When** the Provider verifies if the Consumer already has an active usage contract for the resource\
**And** the Provider invokes the POST /resourceDescriptions/{resourceDescriptionId}/validateExistenceContract API\
**Then** I receive a 404 Not Found response

AC4: A Provider verifies if the Consumer already has an active usage contract for a resource – error case (authenticated)

**Given** an authenticated Consumer authorised to submit a usage contract offer request\
**And** the Consumer submits a usage contract offer request related to a resource description\
**And** the usage contract offer request is sent to the Provider\
**When** the Provider verifies if the Consumer already has an active usage contract for the resource\
**And** the Provider invokes the POST /resourceDescriptions/{resourceDescriptionId}/validateExistenceContract API\
**And** the request cannot be properly fulfilled\
**Then** an appropriate error response is returned (e.g. 400, 406, 415, 500)

AC5: A Provider verifies if the Consumer already has an active usage contract for a resource – unauthenticated case

**Given** an unauthenticated Consumer\
**And** the Consumer submits a usage contract offer request related to a resource description\
**And** the usage contract offer request is sent to the Provider\
**When** the Provider verifies if the Consumer already has an active usage contract for the resource\
**And** the Provider invokes the POST /resourceDescriptions/{resourceDescriptionId}/validateExistenceContract API\
**Then** the request is rejected with a 401 Unauthorised error

AC6: A Provider verifies if the Consumer already has an active usage contract for a resource – error case (authenticated with unauthorised role)

**Given** I am authenticated as a Consumer, without a role authorised to submit a usage contract offer request\
**And** the Consumer submits a usage contract offer request related to a resource description\
**And** the usage contract offer request is sent to the Provider\
**When** the Provider verifies if the Consumer already has an active usage contract for the resource\
**And** the Provider invokes the POST /resourceDescriptions/{resourceDescriptionId}/validateExistenceContract API\
**Then** the request is rejected with a 403 Forbidden
