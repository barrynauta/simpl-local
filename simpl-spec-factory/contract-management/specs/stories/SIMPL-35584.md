# SIMPL-35584: [API] Contract Manager validates and signs contract agreement
- Status: PBI For DG Review
- Type: Story
- Created: 2026-10-22, updated: 2026-10-29
- Source: https://jira.simplprogramme.eu/browse/SIMPL-35584 (collected 2026-10-29)

## Description and acceptance criteria

**As a** EDC connector on the provider side\
**I want** to ask the Contract Manager, via an API, to validate the consumer VC and sign the contract agreement on the provider side\
**So that** the contract is signed on the provider side

Acceptance Criteria:

**AC1: Contract Manager validates the consumer VC and signs the contract (Positive scenario)**\
**Given** the EDC connector of a data space Provider with an API endpoint for validation and signing\
**When** the EDC connector sends a POST request to the API endpoint /credentials/agreements/{contractAgreementId}/definitions/{contractDefinitionId}/validateAndIssue\
**Then** the API returns a 201 Created response\
**And** the VC from the consumer side is validated\
**And** the contract is signed on the provider side

**AC2: Contract Manager validates and signs the contract (Negative scenario – Unauthorized)**\
**Given** the EDC connector is not authenticated\
**When** the EDC connector sends a POST request to the API endpoint /credentials/agreements/{contractAgreementId}/definitions/{contractDefinitionId}/validateAndIssue\
**Then** the API returns a 401 Unauthorized response, indicating insufficient permissions

**AC3: Contract Manager validates and signs the contract (Negative scenario – Called on the consumer side)**\
**Given** the Contract Manager of a data space Consumer\
**When** the EDC connector sends a POST request to the API endpoint /credentials/agreements/{contractAgreementId}/definitions/{contractDefinitionId}/validateAndIssue\
**Then** the API returns a 400 Bad Request response

Technical Description:\
Handler of new endpoint: POST /credentials/agreements/{contractAgreementId}/definitions/{contractDefinitionId}/validateAndIssue in the Contract Manager will validate the consumer's VC and sign the contract on the provider side.

The API endpoint handler should (only when called on the provider side):\
* Validate the consumer VC:\
** Get the VC from the consumer using the new EDC endpoint (VC exchange flow: CM provider → EDC provider → EDC consumer → CM consumer)\
** Technical validation: check the signature and data consistency using the VC Issuer validation endpoint (existing functionality)\
** Business validation: compare the VC payload with the contract data received from EDC\
* Sign the contract on the provider side (existing functionality):\
** Sign the contract data using the Signer Service\
** Create the VC using the VC Issuer service\
** Store the VC in the wallet service\
** Store the contract data in the Contract DB\
** Inform EDC by calling the sign endpoint

Dependencies: SIMPL-35587 (API definition); SIMPL-35440 (GET VC endpoint on the consumer Contract Manager); EDC VC exchange endpoint GET /vcExchange/{contractNegotiationId}/request (Connector team).
