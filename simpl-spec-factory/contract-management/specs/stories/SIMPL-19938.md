# SIMPL-19938: Provider stores signed usage contract securely in digital wallet
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-10-24, updated: 2026-08-12
- Source: https://jira.simplprogramme.eu/browse/SIMPL-19938 (collected 2026-10-29)

## Description and acceptance criteria

**Why**: Provider stores signed usage contract securely in digital wallet for reference purposes

**What**:

**As a** Provider,\
**I want** to store the fully signed usage contract in a secure, machine-readable format,\
**So that** it can be referenced in the future and protected against unauthorized access

**Acceptance Criteria**

- **AC1 - Storing contract successfully in digital wallet:**\
**Given** that I am authenticated as a Provider\
**And** I receive a signed usage contract from a Consumer\
**And** I digitally sign the usage contract\
**When** my digital wallet is ready for use\
**Then** I store securely the fully-signed usage contract in my digital wallet\
**And** the fully-signed usage contract is archived\
**And** it is available in a machine-readable format for reference purposes\
**And** its access is restricted to authorized roles.

**AC1 - Storing contract successfully in digital wallet:**\
**Given** a fully signed usage contract is received by the Provider\
**And** the Provider has validated contract integrity and signatures\
**When** the contract is processed for storage\
**Then** the contract is securely stored in the Provider digital wallet\
**And** the contract is retrievable via Contract Manager API\
**And** access is restricted to authorized roles

- **AC2 - Digital wallet is unavailable:**\
**Given** that I am authenticated as a Provider\
**And** I receive a signed usage contract from a Consumer\
**And** I digitally sign the usage contract\
**And** my digital wallet is not available\
**When** I archive the fully-signed usage contract in my digital wallet for reference purposes\
**Then** I receive an error message stating "Secure storage location unavailable"\
**And** I am requested to specify another secure location for archiving the contract.

**AC2 - Digital wallet is unavailable:**\
**Given** a fully signed usage contract is received by the Provider\
**And** the Provider has validated contract integrity and signatures\
**When** the contract cannot be stored due to digital wallet unavailability\
**Then** an error is returned indicating that the secure storage location is unavailable\
**And** the Provider is requested to specify an alternative secure storage location

- **AC3 - Digital wallet is full:**\
**Given** that I am authenticated as a Provider\
**And** I receive a signed usage contract from a Consumer\
**And** I digitally sign the usage contract\
**And** my wallet is lacking available capacity\
**When** I archive the fully-signed usage contract in my digital wallet for reference purposes\
**Then** I receive an error message stating "Secure storage location is full"\
**And** I am requested to specify another secure location for archiving the contract.

**AC3 - Digital wallet is full:**\
**Given** a fully signed usage contract is received by the Provider\
**And** the Provider has validated contract integrity and signatures\
**When** the contract cannot be stored due to insufficient wallet capacity\
**Then** an error is returned indicating that the secure storage location is full\
**And** the Provider is requested to specify an alternative secure storage location

- **AC4 - Digital wallet is corrupted:**\
**Given** that I am authenticated as a Provider\
**And** I receive a signed usage contract from a Consumer\
**And** I digitally sign the usage contract\
**And** my wallet is corrupted\
**When** I archive the fully-signed usage contract in my digital wallet for reference purposes\
**Then** I receive an error message stating "Secure storage location is corrupted"\
**And** I am requested to specify another secure location for archiving the contract.

**AC4 - Digital wallet is corrupted:**\
**Given** a fully signed usage contract is received by the Provider\
**And** the Provider has validated contract integrity and signatures\
**When** the contract cannot be stored due to wallet corruption\
**Then** an error is returned indicating that the secure storage location is corrupted\
**And** the Provider is requested to specify an alternative secure storage location

- **AC5 - Contract validation failure: (ADDED)**\
**Given** a usage contract is received by the Provider\
**When** contract integrity or signature validation fails\
**Then** the contract is not stored\
**And** an error is returned indicating validation failure

**Technical info**\
- Use decentralized identifier (DID) to verify Consumer's signature (VC)\
- Ensure contract content integrity (e.g., hash comparison)
