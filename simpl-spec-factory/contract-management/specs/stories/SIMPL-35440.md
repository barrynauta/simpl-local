# SIMPL-35440: [API] Contract Manager returns VC for contract for given negotiation ID
- Status: PBI For DG Review
- Type: Story
- Created: 2026-10-21, updated: 2026-10-29
- Source: https://jira.simplprogramme.eu/browse/SIMPL-35440 (collected 2026-10-29)

## Description and acceptance criteria

**As a** EDC connector\
**I want** to retrieve, via an API, the VC for a given contract negotiation ID\
**So that** I can provide it to the other participant during contract validation

Acceptance Criteria:

AC1: A Participant retrieves a VC (Positive scenario)\
**Given** the participant that has already signed the contract for the given contract negotiation ID and stored the VC is the wallet\
**And** the EDC connector of a data space Participant with the CM API endpoint: GET /verifications/{contractNegotiationId}/vc\
**When** the EDC connector sends a GET request to the CM API endpoint,\
**Then** the API returns a 200 OK response with a response body containing the VC

AC2: A Participant retrieves a VC (Negative scenario – Contract not signed yet)\
**Given** the EDC connector of a data space Participant with the API endpoint GET /verifications/{contractNegotiationId}/vc\
**And** the participant didn't signt the contract yet, so VC is not stored in the wallet\
**When** the EDC connector sends a GET request to the API endpoint\
**Then** the API returns a 404 Not Found response

AC3: A Participant retrieves a VC (Negative scenario – Unauthorized)\
**Given** the EDC connector is not authenticated\
**When** the EDC connector sends a GET request to the API endpoint\
**Then** the API returns a 401 Unauthorized response, indicating insufficient permissions

Technical details:

The API endpoint handler should:\
- Check whether the contractNegotiationId exists in the Contract Manager DB\
- Collect the VC for the given contractNegotiationId from the wallet service\
- Return the VC

Input: contractNegotiationId (path parameter).\
Output: json containing VC (200 OK).\
Implementation on both sides - consumer and provider.
