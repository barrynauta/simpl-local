# SIMPL-35660: Contract Manager signs contract on consumer side
- Status: For PSO Review
- Type: Story
- Created: 2026-10-22, updated: 2026-10-29
- Source: https://jira.simplprogramme.eu/browse/SIMPL-35660 (collected 2026-10-29)

## Description and acceptance criteria

**As a** Contract UI backend\
**I want** to start the signing process in Contract Manager on the consumer side via the existing API\
**So that** the contract is signed on the consumer side and the result is sent to EDC

Acceptance Criteria:

**AC1: Contract Manager signs the contract after approval from the Contract UI backend (Positive scenario)**\
**Given** the Contract UI backend of a data space Consumer with an API endpoint to accept the contract\
**When** the Contract UI backend sends a POST request to the API endpoint /contractOffers/{contractNegotiationId}/{operation} with the accept operation\
**Then** the API returns a 201 Created response\
**And** the contract is signed on the consumer side\
**And** the EDC endpoint /signed is called

**AC2: Contract Manager signs the contract after approval from the Contract UI backend (Negative scenario – Unauthorized)**\
**Given** the Contract UI backend is not authenticated\
**When** the Contract UI backend sends a POST request to the API endpoint /contractOffers/{contractNegotiationId}/{operation}\
**Then** the API returns a 401 Unauthorized response, indicating insufficient permissions

**AC3: Consumer rejects the contract offer (Positive scenario – Rejected)**\
**Given** the Contract UI backend of a data space Consumer with an API endpoint to accept or reject the contract\
**When** the Contract UI backend sends a POST request to the API endpoint /contractOffers/{contractNegotiationId}/{operation} with the reject operation\
**Then** the contract is not signed\
**And** the EDC endpoint /signed/{contractNegotiationId}/false is called, so that EDC terminates the negotiation

Technical details:

The API endpoint handler for existing endpoint:\
POST /contractOffers/{contractNegotiationId}/{operation}\
should (only when called on the consumer side):\
* On operation = accept – sign the contract on the consumer side (existing functionality):\
** Get contract data stored in CM DB\
** Sign the contract data using the Signer Service (already implemented)\
** Create the VC using the VC Issuer service (already implemented)\
** Store the VC in the wallet service (already implemented)\
** Inform EDC by calling the /signed/{contractNegotiationId}/true endpoint (already implemented)\
* On operation = reject – do not sign; inform EDC by calling /signed/{contractNegotiationId}/false
