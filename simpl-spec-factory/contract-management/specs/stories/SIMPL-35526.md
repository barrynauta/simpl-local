# SIMPL-35526: Contract Manager prepares contract data for contract UI
- Status: FOR SC TO RESPOND
- Type: Story
- Created: 2026-10-21, updated: 2026-10-29
- Source: https://jira.simplprogramme.eu/browse/SIMPL-35526 (collected 2026-10-29)

## Description and acceptance criteria

**As a** EDC connector on the consumer side\
**I want** to ask the Contract Manager, via an API, to prepare the contract offer data\
**So that** the user can review the usage contract offer in the Contract UI

Acceptance Criteria:

**AC1: Contract Manager prepares contract data (Positive scenario)**\
**Given** the EDC connector of a data space Consumer with an API endpoint for creating contract data\
**When** the EDC connector sends a POST request to the API endpoint /credentials/agreements/{contractAgreementId}/definitions/{contractDefinitionId}/create\
**Then** the API returns a 201 Created response\
**And** the prepared contract offer data is sent to the Contract UI backend\
**And** the Consumer user is notified that a usage contract offer is available for review

**AC2: Contract Manager prepares contract data (Negative scenario – Unauthorized)**\
**Given** the EDC connector is not authenticated\
**When** the EDC connector sends a POST request to the API endpoint /credentials/agreements/{contractAgreementId}/definitions/{contractDefinitionId}/create\
**Then** the API returns a 401 Unauthorized response, indicating insufficient permissions

Technical notes:\
This story modifies the existing implementation of /credentials/agreements/{contractAgreementId}/definitions/{contractDefinitionId}/create endpoint.\
Changes in endpoint handler are:\
- Execute on the consumer side instead of the provider side\
- Do not call EDC callback endpoint afterwards\
- Call the Contract UI backend to store the prepared data (POST /contractOffers/{contractNegotiationId})\
- Get the user email\
- Change the way resource data is collected from the catalogue (use selfDescriptionId instead of assetId + contractDefinitionId)\
- Collect the user email and notify the user\
- Store contract data in CM DB
