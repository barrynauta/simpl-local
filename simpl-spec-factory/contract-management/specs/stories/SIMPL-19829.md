# SIMPL-19829: [Replaced] [API] - API to create usage contract offer
- Status: DevTeam PBI In Progress
- Type: Story
- Created: 2025-10-22, updated: 2026-09-07
- Source: https://jira.simplprogramme.eu/browse/SIMPL-19829 (collected 2026-10-29)

## Description and acceptance criteria

Why: To create the machine-readable format of the usage contract offer based on the Consumer's request.

What:

**As a** Provider handling a usage contract request\
**I want** to create the machine-readable usage contract offer for the requested resource description and the requesting Consumer\
**So that** the usage contract offer is available for further processing in the contract negotiation flow.

Acceptance Criteria:

*AC1 - Successful creation*\
**Given** that the Provider has received from a Consumer a usage contract request for a specific resource description\
**And** the usage contract request has passed all prerequisite checks (access policies, duplicate-contract check)\
**And** the usage contract request is valid (all required fields are provided, and all fields have valid values)\
**When** the Provider's Contract Manager API is called to create the machine-readable usage contract offer\
**Then** the system returns an ACK (acknowledge) message with HTTP status code 201 (OK)\
**And** a machine-readable usage contract offer for the requesting Consumer and the requested resource description is created in JSON format\
**And** the usage contract offer is returned to the dedicated Provider Connector endpoint for further processing

*AC2 - Validation error handling*\
**Given** that the Provider has received from a Consumer a usage contract request for a specific resource description\
**And** the usage contract request contains invalid or missing required fields\
**When** the Provider's Contract Manager API is called to create the machine-readable usage contract offer\
**Then** the system returns HTTP status code 400 (Bad Request)\
**And** the error response contains a detailed validation error message in JSON format\
**And** the error event is logged\
**And** the contract establishment process is prevented from proceeding\
**And** no contract offer is created

*AC3 - Unauthorized*\
**Given** that the Provider has received from a Consumer a usage contract request for a specific resource description\
**And** the request to the Contract Manager API contains an invalid, expired, or missing API key\
**When** the Provider's Contract Manager API is called to create the machine-readable usage contract offer\
**Then** the system returns HTTP status code 401 (Unauthorized)\
**And** the error response contains a JSON payload with detailed validation error messages\
**And** the error event is logged\
**And** the contract establishment process is prevented from proceeding\
**And** no contract offer is created

*AC4 - Method Not Allowed*\
**Given** that the Provider has received from a Consumer a usage contract request for a specific resource description\
**And** the Contract Manager API endpoint is called using an unsupported HTTP method\
**When** the Provider's Contract Manager API is called to create the machine-readable usage contract offer\
**Then** the system returns HTTP status code 405 (Method Not Allowed)\
**And** the error response contains a JSON payload with detailed error messages\
**And** the error event is logged\
**And** the contract establishment process is prevented from proceeding\
**And** no contract offer is created

*AC5 - Unsupported Media Type*\
**Given** that the Provider has received from a Consumer a usage contract request for a specific resource description\
**And** the request to the Contract Manager API is sent with an unsupported Content-Type header\
**When** the Provider's Contract Manager API is called to create the machine-readable usage contract offer\
**Then** the system returns HTTP status code 415 (Unsupported Media Type)\
**And** the error response contains a JSON payload with detailed error messages\
**And** the error event is logged\
**And** the contract establishment process is prevented from proceeding\
**And** no contract offer is created

*AC6 - System error handling*\
**Given** that the Provider has received from a Consumer a usage contract request for a specific resource description\
**And** the usage contract request has passed all prerequisite checks\
**When** the Provider's Contract Manager API is called to create the machine-readable usage contract offer\
**And** a system error occurs (e.g., database unavailable, internal processing error)\
**Then** the system returns HTTP status code 500 (Internal Server Error)\
**And** the error response contains a JSON payload with detailed error messages\
**And** the error event is logged\
**And** the contract establishment process is prevented from proceeding\
**And** no contract offer is created

Technical Info:\
* Machine-readable format: response format in JSON\
**When** EDC calls the provider’s Contract Manager endpoint, it only receives an ACK as confirmation of receipt of the message. This is because the EDC behaves as a state machine. The actual response is sent later in a separate call: “notify EDC":\
[https://confluence.simplprogramme.eu/display/SIMPL/TCV+Dynamic+-+BP+07+-+Consumer+and+Provider+establish+a+usage+contract+for+selected+catalogue+items]\
* Endpoint: POST /credentials/agreements/{contractAgreementId}/definitions/{contractDefinitionId}/create\
* HTTP Status Codes:

```\
201: OK (acknowledgement message)\
400: Bad Request\
401: Unauthorized\
405: Method Not Allowed\
415: Unsupported Media Type\
500: Server Error\
```

Additional Notes:

This task is linking to the EDC connector to ensure API availability and proper error handling - on the EDC side need:\
