# SIMPL-21928: Consumer signs the usage contract offer received from a Provider
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-12-08, updated: 2026-10-23
- Source: https://jira.simplprogramme.eu/browse/SIMPL-21928 (collected 2026-10-29)

## Description and acceptance criteria

**Why**: To allow the Consumer to use a specific resource based on a contract agreement.

**What**:

**As a** Consumer,\
**I want** to digitally sign the usage contract offer I have reviewed and accepted\
**So that** I confirm my acceptance of this usage contract offer for this resource.

**Acceptance Criteria**:

AC1 Successful Consumer signing

**Given** an authenticated Consumer user is allowed to sign the usage contract offer\
**And** the usage contract offer is ready for signing\
**When** the signing process is triggered\
**Then** Contract Manager completes the Consumer signing process\
**And** the signing result is registered for the usage contract offer.

AC2 Signing uses agreed backend services

**Given** the Consumer signing process is triggered\
**And** the usage contract offer is ready for signing\
**When** Contract Manager processes the signing request\
**Then** Contract Manager creates or requests the required signature credential / signing payload using the agreed backend signing flow\
**And** the signing result is persisted or registered for the usage contract offer\
**And** the operation is traceable using the usage contract offer identifier / contractNegotiationId where available\
**And** the usage contract offer is not marked as signed unless the backend signing flow completes successfully.

AC3 Unauthorized signing is rejected

**Given** the user is not authenticated or is not allowed to sign the usage contract offer\
**When** the signing process is triggered\
**Then** the signing request is rejected\
**And** the usage contract offer is not marked as signed.

AC4 Signing failure is handled

**Given** the Consumer signing process is triggered\
**When** the signing process fails\
**Then** the signing result is not registered as successful\
**And** the usage contract offer is not marked as signed\
**And** the failure is traceable using available logs / error information.

**Technical Info**:

The signing process is backend-driven.

The UI / BFF may trigger the signing action, but UI button behaviour is outside the scope of this story.

Contract Manager orchestrates the Consumer signing process at usage contract offer level and uses the agreed signing / credential issuing services according to the implemented signing flow.

This story must not assume an “unsigned VC” as a formal intermediate artefact.
