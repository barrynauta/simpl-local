# SIMPL-35677: [API] Contract Manager verify contract on consumer side
- Status: FOR SC TO RESPOND
- Type: Story
- Created: 2026-10-22, updated: 2026-10-29
- Source: https://jira.simplprogramme.eu/browse/SIMPL-35677 (collected 2026-10-29)

## Description and acceptance criteria

**As a** EDC on the consumer side\
**I want** to verify the VC from the provider via the CM API\
**So that** I am able to finalize the contract

Acceptance Criteria:

**AC1: EDC uses the Contract Manager to verify the VC from the provider (Positive scenario)**\
**Given** the EDC of a data space Consumer with an API endpoint to verify the VC\
**When** the EDC sends a POST request to the API endpoint /verifications/{contractNegotiationId}\
**Then** the API returns a 202 Created response\
**And** the providers VC is verified on the consumer side\
**And** the EDC endpoint /isValid/{contractNegotiationId}/true is called

**AC2: EDC uses the Contract Manager to verify the VC from the provider (Negative scenario – Unauthorized)**\
**Given** the EDC is not authenticated\
**When** the EDC sends a POST request to the API endpoint /verifications/{contractNegotiationId}\
**Then** the API returns a 401 Unauthorized response, indicating insufficient permissions

**AC3: EDC uses the Contract Manager to verify the VC from the provider (Negative scenario – VC not valid)**\
**Given** the EDC of a data space Consumer with an API endpoint to verify the VC\
**When** the EDC sends a POST request to the API endpoint /verifications/{contractNegotiationId}, and the provider VC fails the technical or business validation\
**Then** the EDC endpoint /isValid/{contractNegotiationId}/false is called

**AC4: EDC uses the Contract Manager to verify the VC from the provider (Negative scenario – Called on the provider side)**\
**Given** the Contract Manager of a data space Provider\
**When** the EDC sends a POST request to the API endpoint /verifications/{contractNegotiationId}\
**Then** the API returns a 400 Bad Request response

Technical Description:\
The API endpoint handler should (only when called on the consumer side):\
- Verify the VC from the provider:\
- Get the providers VC using the new EDC endpoint (VC exchange flow: CM consumer → EDC consumer → EDC provider → CM provider)\
- Technical validation: check the signature and data consistency using the VC Issuer validation endpoint (existing functionality)\
- Business validation: compare the VC payload with the contract data stored in the Contract Manager DB\
- Inform EDC about the result using /isValid/{contractNegotiationId}/{isValid} (true or false)
