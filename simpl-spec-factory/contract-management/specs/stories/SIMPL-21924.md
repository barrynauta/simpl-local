# SIMPL-21924: [UI] Consumer requests a contract offer for using a resource via UI
- Status: PBI Defined
- Type: Story
- Created: 2025-12-08, updated: 2026-10-20
- Source: https://jira.simplprogramme.eu/browse/SIMPL-21924 (collected 2026-10-29)

## Description and acceptance criteria

**As a** Consumer end user\
**I want** to to request a usage contract offer for a resource I found in the catalogue via UI\
**So that** I can check the usage contract offer and decide whether I want to proceed with the contract establishment

Technical Description

According to the attached mockup, after clicking the Get Data button in the Catalogue UI to initiate a Contract Negotiation, the user will be presented with a confirmation popup containing a button that redirects them to the Contract Manager UI, where they can proceed with the contract signing process.

In light of this workflow, the technical polling mechanism towards the connector must be disabled while awaiting the outcome of the Contract Negotiation. Therefore, the Catalogue UI shall invoke the startNegotiation API and, upon receiving a successful response, update the negotiation status accordingly without triggering any polling process. The negotiation outcome will be managed through the subsequent signing flow executed within the Contract Manager UI.

Acceptance Criteria

AC1 - A Provider requests a usage contract via UI

**Given** I am authenticated as a Consumer end user\
**And** I have a role authorising catalogue search and contract management\
**When** I have found a resource in the catalogue\
**Then** I can click on a button to request a usage contract offer

AC2 - A Provider successfully finishes requesting a usage contract via UI

**Given** I am authenticated as a Consumer end user\
**And** I have a role authorising catalogue search and contract management\
**And** I have found a resource in the catalogue\
**When** I click on the button to request a usage contract offer\
**And** I am allowed to request a usage contract for this resource based on the contract access policies\
**And** I do not have an active usage contract for this resource already\
**Then** I see the result of the positive validation of the usage contract offer request\
**And** I see a link to the contract manager UI for further follow up of the contract negotiation\
**And** A usage contract with the status "In progress" is created and stored in the contract manager

AC3 - A Provider requests a usage contract offer via UI but is not allowed to request a usage contract for this resource based on the contract access policies

**Given** I am authenticated as a Consumer end user\
**And** I have a role authorising catalogue search and contract management\
**And** I have found a resource in the catalogue\
**And** I am not allowed to request a usage contract for this resource based on the contract access policies\
**When** I click on the button to request a usage contract offer\
**Then** the catalogue UI displays an error message related to the validation of the access policies

AC4 - A Provider requests a usage contract offer via UI but already has an active usage contract for the resource

**Given** I am authenticated as a Consumer end user\
**And** I have a role authorising catalogue search and contract management\
**And** I have found a resource in the catalogue\
**And** I already have an active usage contract for the resource\
**When** I click on the button to request a usage contract offer\
**Then** the catalogue UI displays an error message that I already have an active usage contract for the resource
