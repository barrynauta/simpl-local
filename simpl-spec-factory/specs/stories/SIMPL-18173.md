# SIMPL-18173: Create a new version of a vocabulary via API
- Status: Ready for DG Acceptance
- Type: Story
- Created: 2025-09-10, updated: 2026-08-12
- Source: https://jira.simplprogramme.eu/browse/SIMPL-18173 (collected 2026-10-27)

## Description and acceptance criteria

**As a** Governance Authority\
**I want** to create a new version of an existing vocabulary via the API\
**So that** I can automate versioning or integrate it into workflows

*Acceptance Criteria*

*Happy Path*\
**Given** I am authenticated and authorised as a Governance Authority\
**When** I submit updated metadata and content for an existing vocabulary via the API\
**And** the submitted vocabulary passes the required validation\
**Then** the API creates a new version linked to the existing vocabulary\
**And** the system automatically assigns the next version identifier\
**And** the newly created version is set to ACTIVE\
**And** all previous versions of the same vocabulary are set to DEPRECATED\
**And** the response contains the new version details

*Negative Scenarios*

**Given** I am authenticated\
**When** I submit invalid or incomplete vocabulary data\
**Then** the request is rejected with validation feedback

**Given** I am authenticated\
**When** I request creation of a version for a vocabulary that does not exist\
**Then** the request is rejected

**Given** I am authenticated but not authorised as a Governance Authority\
**When** I attempt to create a new version\
**Then** the request is rejected due to insufficient permissions

**Given** I am not authenticated\
**When** I attempt to create a new version without being authenticated\
**Then** the request is rejected

**Given** I submit the request in an unsupported format\
**When** the system cannot process the request\
**Then** the request is rejected



Technical Info:\
- the versioning should be incremental using the same versioning library as schema management
