# SIMPL-18196: Role-based access control for vocabulary management API
- Status: Ready for DG Acceptance
- Type: Story
- Created: 2025-09-10, updated: 2026-08-12

## Description and acceptance criteria

**As a** Governance Authority,\
**I want** the API to enforce role-based access control on all vocabulary management actions,\
**So that** unauthorized users cannot perform restricted vocabulary actions.

Acceptance Criteria:

Scenario: Access control enforcement

**Given** I am authenticated with a valid Bearer token\
**And** I have the vocabulary management role\
**When** I invoke any Vocabulary Management API endpoint\
**Then** the API authorizes and processes the request.

Scenario: Unauthorized role access

**Given** I am authenticated with a valid Bearer token\
**But** I do not have the vocabulary management role\
**When** I invoke any Vocabulary Management API endpoint\
**Then** the API returns a `403 Forbidden` response.

Scenario: Unauthenticated access

**Given** I am not authenticated\
**When** I invoke any Vocabulary Management API endpoint\
**Then** the API denies access and returns an authentication error response.

Scenario: Endpoint protection

**Given** the Vocabulary Management API is deployed

**When** I want to authenticate for the endpoints of this API\
**Then** all vocabulary-related endpoints require the authentication token and the Tier1 Role validation\
----

Technical Info: [https://confluence.simplprogramme.eu/spaces/SIMPL/pages/137235370/R07.02+Vocabulary+Management+-+Tech+Description]

The Vocabulary Management API enforces role-based access control based on the following roles:\
* `GA_VOCABULARY_VIEWER`: for read-only operations across vocabulary and version resources.\
* `GA_VOCABULARY_ADMIN`: for both read and write operations, including lifecycle and reference management.\
* This is Tier 1 authentication
