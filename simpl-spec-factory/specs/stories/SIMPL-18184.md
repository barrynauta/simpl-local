# SIMPL-18184: Automatic check for deprecated vocabularies during new version creation in UI
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-09-10, updated: 2026-09-25
- Source: https://jira.simplprogramme.eu/browse/SIMPL-18184 (copied 2026-10-27)

## Description and acceptance criteria (as shown on the Jira issue page)

As a Governance Authority,
I want Simpl-Open to automatically check the status of vocabulary versions I reuse when creating a new version
so that I avoid reusing deprecated versions

Acceptance Criteria

Given I am authenticated and authorised as a Governance Authority user with vocabulary management admin rights
And I am creating a new vocabulary version
And I reference one or more existing vocabulary versions
And all referenced vocabulary versions have status ACTIVE
When I submit the new vocabulary version for creation
Then Simpl-Open validates the status of each referenced vocabulary version
And the validation passes
And the new vocabulary version creation process can continue
And no deprecated-version warning or error is returned

Given I am authenticated and authorised as a Governance Authority user with vocabulary management admin rights
And I am creating a new vocabulary version
And I reference one or more existing vocabulary versions
And at least one referenced vocabulary version has status DEPRECATED
When I submit the new vocabulary version for creation
Then Simpl-Open validates the status of each referenced vocabulary version
And the validation fails for each referenced version with status DEPRECATED
And the new vocabulary version is not created
And no existing vocabulary versions are changed
And the API/UI returns a clear validation error identifying each deprecated vocabulary version
And the error message recommends using the latest ACTIVE version where available

Given I am authenticated and authorised as a Governance Authority user with vocabulary management admin rights
And I am creating a new vocabulary version
And I reference a vocabulary version that does not exist
When I submit the new vocabulary version for creation
Then Simpl-Open validates the referenced vocabulary version
And the validation fails
And the new vocabulary version is not created
And the API/UI returns a clear validation error identifying the missing vocabulary version

Given I am authenticated and authorised as a Governance Authority user with vocabulary management admin rights
And I am creating a new vocabulary version in the Vocabulary Management UI
When I select or reference a vocabulary version with status DEPRECATED
Then Simpl-Open displays a clear warning that the selected version is deprecated
And the warning identifies the deprecated vocabulary version
And the warning recommends selecting the latest ACTIVE version where available

 

Notes:

this is only for INTERNAL vocabularies (managed by vocabulary management), a vocabulary may reference external vocabularies but we cannot enforce their versioning and deprecation status
so we check vocabularies against internally created vocabularies
