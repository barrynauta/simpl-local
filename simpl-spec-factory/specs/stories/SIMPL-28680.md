# SIMPL-28680: [API] Governance Authority update metadata quality governance rules by publishing an updated Metadata Quality Profile

## Description and acceptance criteria (as shown on the Jira issue page)

As a Governance Authority End User,
I want to update metadata quality governance rules via API by submitting an updated Metadata Quality Profile RDF document in Schema Manager,
so that governance changes are applied consistently from a controlled semantic source.

Technical Details:
Profile update via API creates a new active Metadata Quality Profile version instead of mutating historical versions in place
Governance definitions (dimensions with weights, classifications, score ranges, thresholds) are fully sourced from the uploaded RDF profile
Authorization is enforced before semantic processing; unauthorized attempts return authorization errors
Validation is split into syntax validation (RDF parse) and semantic/vocabulary validation (Metadata Quality Profile structure and constraints)
Validation errors use non-sensitive error codes and messages suitable for API feedback
Acceptance Criteria
AC1

Given I am authenticated and authorized to manage metadata quality governance
When I submit a POST request to {{/metadataQualityProfiles/

{metadataQualityProfileName}

/versions}} with a valid RDF document in the payload,
Then the API accepts the RDF document, creates a new version of the profile, and returns a 201 Created with a Location header pointing to the new version.

Given I upload a syntactically valid RDF document conforming to the Metadata Quality Profile vocabulary
When Schema Manager processes the update
Then updated governance definitions are persisted in the new active profile version
And previous profile versions remain available for traceability.

AC3

Given I upload a document that is not valid RDF syntax
When Schema Manager validates the document
Then the update is rejected
And an error is returned with a non-sensitive code and syntax-focused description.

AC4

Given I upload a document that is not valid RDF semantic
When Schema Manager validates the document
Then the update is rejected
And an error is returned with a non-sensitive code and semantic-focused description.

AC5

Given I am not authorized to manage metadata quality governance
When I attempt to update the Metadata Quality Profile via API
Then Simpl-Open returns an authorization error.

AC6

Given I upload a new version for a non existing MQP
When Schema Manager processes the update
Then the update is rejected
And an error is returned with a non-sensitive code and syntax-focused description.

Note:

Validation is done using same functionality as Schema Manager
For semantic validation Schema Manager resolves vocabularies against Vocabulary Manager - the Metadata Quality Profile vocabulary needs to be present there (out of scope)
