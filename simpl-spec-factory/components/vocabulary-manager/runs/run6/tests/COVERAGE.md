## UI run (step 60)

`./run.sh ui` runs every `@ui` scenario with Playwright for Python (Chromium, headless) and writes `reports/ui.json`. Each scenario gets a new browser context (no stored session) and signs in on the Keycloak login page of E1. Elements are found by the texts, labels and column names of the decisions (D31 to D37, D46, D60) and criteria; labels no decision fixes match case-insensitively as a whole word ('Name' matches 'Name contains', 'Download' matches 'Download vocabulary'). Only the routes of D31 are written in the scenarios. No CSS class, test id or build route is used.

Run of 19 Nov 2026 against the run 6 build: 41 cases (37 UI plus 4 accessibility), 40 pass, 1 fails. No scenario is `@manual`.

### Failures

- ui_create_and_version.feature 'A file above 5 MB is refused in the browser' (D13, D15, D37). Build differs from the decisions. The UI refuses the file and disables Submit, but shows the refusal as a message above the form ('Uploaded vocabulary file is too large...'), not as a field error under 'Vocabulary file'. D37 puts errors found before submit under the field and only server errors (400, 409, 413) above the form. The scenario is kept. Question for the owners: is the browser size check a field error (D37) or the 413 message of D15?
