**The five most important findings**

1. **No circuit breaker on the store or the identity provider (CODE-46, ARCH-34).** The build has timeouts, read retries and fail-closed 503s, but no breaker. Under a slow store, every request still waits the full 10 s (reads) or 45 s (writes), and the 64 Tomcat threads fill up. Neither `DEVIATIONS.md` nor `REUSE.md` mentions this.
2. **The code can scale out, the deployment cannot (ARCH-07, MACH-09).** `compose.yaml` pins the backend to `ipv4_address: 10.209.9.10` and binds `MANAGEMENT_ADDRESS` to that IP, so `--scale backend=2` fails. `QUALITY.md` Q4 and `operations.md` say several instances "may run". That is true of the code (D82, `StoreModelTest`), not of the delivered stack.
3. **The exception model has no shared base and no error-code enum (CODE-33, CODE-44).** All exceptions extend `RuntimeException` directly, and problem types are string constants in `Problems`. The single `ApiExceptionHandler` is good (CODE-34 to CODE-36 met), but these two rules are silently skipped.
4. **Logs are logstash JSON, not the Simpl log format (CODE-21, CODE-52), and nothing ships them (SEC-11).** D96 is met. The programme logging contract is not followed and not recorded as a deviation.
5. **REUSE.md is good but not complete (REUSE-05, REUSE-07).** These are missing:
   - `ContentChunks`: the file bytes are stored as base64 chunks in Fuseki, although the catalogue offers MinIO for files.
   - The circuit-breaker choice.
   - The catalogue items `api-gateway-authorisation`, `http-client` and `participant-shared-code`.
   - The hand-written query-string parser (`RequestChecks.query`) and link builder (`Representations.link`).

   Also, "Backend for frontend" is the wrong name for a plain nginx reverse proxy.

## 3. Disagreements with the build's own documents

**The build is silent, and I find "not met"**

- **CODE-46 and ARCH-34 (circuit breaker).** Not in `DEVIATIONS.md`. `REUSE.md` turns down Resilience4j for retries but says nothing about a breaker.
- **CODE-33 and CODE-44 (base exception, error-code enum).** Not in `DEVIATIONS.md`.
- **CODE-21 and CODE-52 (Simpl log format).** The build presents D96 logstash JSON as complete.
- **ARCH-22 and ARCH-27.** Not listed. ARCH-27 is covered by D45 and should still be a recorded deviation.

**The build reports "met", and I find "partly"**

- **Scaling (QUALITY.md Q4, operations.md "Scaling").** They say several instances may run. True of the code; false of the compose stack, which fixes the backend IP and the management address. The metrics recipe in `operations.md` also depends on the fixed IP.
- **REUSE.md completeness (REUSE-07, D93).** Missing rows for `ContentChunks`, the circuit breaker, the hand-written query-string and link code, and the catalogue items `api-gateway-authorisation`, `http-client` and `participant-shared-code`.
- **D98 ("management port not on the front network").** Holds for `backend`, not for `backend-store-down`, which binds 8081 on 0.0.0.0 on the front network.

**Small inaccuracies**

- `QUALITY.md` says the limits are under `vocabulary-manager.limits`. `application.yaml` uses `vm.limits`.
- The `RouteTable` javadoc points to a non-existent `RouteTableTest`.
- D44 says keys are fetched "at start". `RealmKeySource` fetches lazily: on the first token, or on the first `/v1/health` call, which the compose health check triggers within 5 s.

**Where I agree with the build's self-assessment**

`DEVIATIONS.md` records OWT-A04, OWT-A07, OWT-A09, OWASP-05, OPS-37, the Keycloak dev mode and the PrimeVue gap correctly. `QUALITY.md` is honest that Q1 was not proven at design load.

## 4. Findings for the next run

1. **Add a decision on circuit breaking** for the store and the key endpoint: thresholds, half-open probe, and what the caller sees. Otherwise CODE-46 and ARCH-34 stay unmet in every run. Name Resilience4j as the default in the reuse catalogue.
2. **Add a scaling check to the finish line:** `docker compose up --scale backend=2` must work. Forbid fixed container IPs and bind the management port through a dedicated internal network instead. This makes D82's claim provable at deployment level.
3. **Decide the exception model.** Either supply the shared exception-handling library (CODE-33) and an error-code enum convention (CODE-44), or record in the decisions that the Belgif problem types replace them. Then the writer can list it.
4. **Put the Simpl logging contract (LogWrapper) into the build input**, or decide it is out of scope. Today CODE-21 and CODE-52 cannot be met, and nobody says so.
5. **Make the REUSE.md template enumerate every catalogue entry** (one row each, including "not needed because...") and every own class over about 100 lines doing infrastructure work. Step 70 could check this mechanically against `reuse-catalogue.yaml`.
6. **Have DEVIATIONS.md cover every MUST and SHOULD in step 70's review set,** not "MUST rules plus SHOULDs a decision names". That gap is where the silent misses in section 3 come from.
7. **Give the CDM owner the DATA findings:** search request classes in the CDM, untyped attributes, a duplicated `latestVersion` and `description`, generic timestamp names. They come from the input, not the build.
8. **Delivery-model rules** (ARCH-14, ARCH-24, OPS-29, CODE-45, SEC-12): either add a minimal Helm chart and gateway route file to the brief, or mark these rules not applicable for compose-only factory builds, so they stop showing up as partial every run.
