# Vocabulary Manager

The Vocabulary Manager lets a Governance Authority user publish and maintain the vocabularies of the data space
(business process BP02B, stories SIMPL-181xx, SIMPL-18452 and SIMPL-18559). It stores internal vocabularies as
numbered vocabulary versions of Turtle content, validates each upload (syntax, then semantic rules S1 to S7), keeps a
vocabulary status and a version status (ACTIVE or DEPRECATED), and holds registered external vocabularies (cached
copies of third-party namespaces) so that references to them can be recognised. Consumers such as Schema Manager read
the state through the search and content operations (pull only, D45).

## What runs

| Service | Image | Host port | Role |
|---|---|---|---|
| backend | `vm-factory-run8/backend:1.0.0` (Java 21, Spring Boot 4.1.2) | 8196 (API under `/v1`) | REST API, validation, authorisation |
| ui | `vm-factory-run8/ui:1.0.0` (Vue 3, Vite, nginx) | 4433 | Screens; nginx also proxies `/v1` to the backend |
| keycloak | `quay.io/keycloak/keycloak:26.8.2` | 8193 | Identity provider, realms `simpl` and `simpl-other` imported at start |
| fuseki | `vm-factory-run8/fuseki:6.2.0` (Apache Jena Fuseki) | none (internal network only, D83) | RDF store, dataset `vocabulary` |
| backend-store-down | same as backend, profile `storedown` | 8199 | Backend whose store is unreachable, for the D44 tests |

The backend management port 8081 (health probes, `/actuator/prometheus`) is not published outside the deployment (D67).

## How to run

```
./stack.sh up               # build and start; returns when every service is healthy; no-op when running
./smoke.sh                  # main flow end to end (see below)
./stack.sh store-down-up    # second backend with an unreachable store on port 8199
./stack.sh store-down-down
./stack.sh images           # every image of the stack
./stack.sh down
```

`stack.sh up` writes `.env` with random store and Keycloak admin passwords on first use (no default credentials).
The start command of the build profile is `docker compose -p vm-factory-run8 up -d --build --wait`; `stack.sh up` runs
it with that `.env`.

Test users (realm `simpl`, password `Password1!`): `ga-admin` (GA_VOCABULARY_ADMIN), `ga-viewer`
(GA_VOCABULARY_VIEWER), `ga-norole` (no role). Clients: `vocabulary-manager-ui` (UI, code flow with PKCE),
`vocabulary-tests` (password grant, with the audience mapper), `vocabulary-tests-noaud` (no audience, tokens get 401).
Realm `simpl-other` has a `vocabulary-tests` client for the wrong-issuer case (E7).

```
TOKEN=$(curl -s http://localhost:8193/realms/simpl/protocol/openid-connect/token \
  -d grant_type=password -d client_id=vocabulary-tests -d username=ga-admin -d 'password=Password1!' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')
curl -H "Authorization: Bearer $TOKEN" http://localhost:8196/v1/vocabularies
```

UI: http://localhost:4433 (login through Keycloak).

## Smoke test

`smoke.sh` gets a token for ga-admin, creates a vocabulary, creates version 2, lists with a name filter, downloads the
latest content and compares the bytes, lists the versions and searches both by name and by name and version. It also
checks that ga-viewer gets 403 on create and that a request without a token gets 401.

## Own tests

```
cd backend && mvn verify      # unit and integration tests, JaCoCo report in backend/target/site/jacoco/
ops/backup-restore-test.sh    # backup and restore round trip on the running stack (Q3)
```

## Backup and restore

`ops/backup.sh [dir]` dumps the whole store as N-Quads (with a quad count and a checksum). `ops/restore.sh <file>`
loads the backup into the staging dataset `vocabulary-restore`, checks the count, and only then replaces the dataset
`vocabulary`; it refuses a backup smaller than the live store unless `--allow-smaller` is given. Details in
[architecture.md](architecture.md) and `QUALITY.md`.
