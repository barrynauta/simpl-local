## UI automation (step 60)

Written by hand after `tools/coverage.py`; re-add this section when the file is regenerated.

- Every `@ui` scenario has browser steps (`features/steps/ui_steps.py`, Playwright for Python). `./run.sh ui` runs `@ui and not @manual and not @wip` and writes `reports/ui.json`; axe details go to `reports/axe/`.
- Each scenario opens a new browser context: no stored cookies, storage or login. Login goes through the Keycloak page of E1.
- Elements are found only by decided routes (D31, D74, D163, D180, D210), texts and labels (D18, D34 to D36, D60, D72, D109, D115, D209, D210), roles and names (D75, D90, D163) and the API path `/v1` (E2) for the stubbed answers of D24. No test ids and no names taken from the build.
- Interpretations: a decided action may be a button or a link ("New Vocabulary +", "Register external vocabulary +", "Cancel"); a field error is `aria-invalid="true"` or a non-empty `aria-describedby`/`aria-errormessage` text; on the external vocabularies screen a column after the six D210 columns is accepted only when it holds nothing but the row actions.
- `@manual`: none. Every UI scenario could be automated with the decided names.
