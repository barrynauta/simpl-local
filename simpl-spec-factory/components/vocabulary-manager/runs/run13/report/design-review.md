Both MUST rules that are not met are recorded deviations: CODE-11 (D135) and OPS-37 (no pipeline). Most "partly" verdicts on MUST rules come from work the decisions leave to the platform: TLS, encryption at rest, token-failure limiting and alerting.

**The five most important findings**

1. **The management port can be reached from the front network, against D98.** The backend joins `[store, front]` (`compose.yaml:80`), and `management.server.port=8081` has no `management.server.address` (`application.properties:42`). So `/actuator/prometheus` and the health endpoints can be reached from the proxy and Keycloak containers. D98 says the management port is "not on the front network". This gap is not in `DEVIATIONS.md`, and `QUALITY.md` only says the port is "not published on a host port".
2. **Three routing tables are kept by hand, and `REUSE.md` lists only one.** The three are the Spring MVC mappings, the `OperationCatalog` regex table (`web/OperationCatalog.java:36-38`) and the nginx `map $uri $vm_allow` (`ui/nginx/vocabulary-manager.conf.template`). `HandlerRuleCheck` checks only the first two against each other at start; the nginx map has no check. `REUSE.md` says routing is "Spring MVC (D133)" and does not list `OperationCatalog` as an own router. This is over-engineering forced by the status-code ordering of D67, D139 and D63, and it costs maintenance.
3. **The security gate is own code around Nimbus.** The decisions allow this (D108, D132). Nimbus does the signature, JWK and claims work. The rest is own code: bearer parsing, the algorithm allow-list, the key-id lookup, the key cache and refetch timing, and the role gate (`RequestGateFilter`, `RealmKeyProvider`, `TokenVerifier`). The Spring Security resource server was turned down only to get a particular 401/405/406 order. REUSE-01 is therefore partly met. The code is careful, but it is security code the project now owns.
4. **No pipeline, and lint is not enforced everywhere.** OPS-37 (MUST) is not met. The backend Dockerfile skips Spotless (`-Dspotless.check.skip=true`). The Python scripts (`loadtest.py`, `seed_store.py`, `make_openapi_decided.py`) and the shell scripts have no formatter or linter (CODE-55). Shell scripts parse JSON with `sed` (`scripts/backup-restore-test.sh:8-9`, `smoke.sh:17`).
5. **Production security and availability are deferred, and one NFR target is neither measured nor listed as unmeasured.** The deferred items are no TLS, no encryption at rest, no token-failure limiting, no alerting, and a single Fuseki and Keycloak instance. They are recorded deviations, but nothing in the build closes them. Q3's 99.5 % availability target is neither measured nor declared "not measured" in `QUALITY.md` (NFR-13 partly). Separately, decision Q4 still reads "One backend instance (D81)", although D82 withdrew D81 and the build correctly runs two replicas.

## 3. Disagreements with the build's own documents

**Where I am stricter than the build:**
- **D98, management port.** `QUALITY.md` (Observability) and `docs/architecture.md` describe the management port as internal. The code puts it on the front network (`compose.yaml:80`, no `management.server.address`). This is not in `DEVIATIONS.md`. It affects OWT-A02 and ARCH-30.
- **REUSE-07.** `REUSE.md` says routing is reused from Spring MVC and names only `AcceptCheck` as own code. `OperationCatalog` (a regex router with access rules), `HandlerRuleCheck` and the nginx method map are own routing code and are missing from the table.
- **REUSE-01.** `REUSE.md` presents token handling as Nimbus with "only the fetch timing" as own code. The algorithm allow-list, bearer header parsing and the role gate are own security code as well. The decisions allow it, but the rule is only partly met.
- **NFR-13.** `QUALITY.md` Q3 lists the 99.5 % availability target "as decided", with no measurement and no "not measured, because" line.
- **Small gaps not in DEVIATIONS:** API-10 (singular `/external-vocabulary/searches`), API-35 (no Accept on the update and JWKS calls), API-49 (decision ids in `info.description`), CODE-55 (Python and shell not linted) and REUSE-02 (`sed` parsing JSON in scripts).
- **Coverage figure.** `QUALITY.md` says 94.3 % line coverage; `DEVIATIONS.md` says 94.2 %.

**Where the build is stricter than me:**
- UX-01 and SEC-02 are listed as deviations. I rate them not applicable, because their inputs (UX guidelines, the Secure Development Guideline) do not exist for the factory.

**Where I agree:** All other recorded deviations match the code: CODE-11, CODE-21, CODE-33, CODE-45, CODE-52, OPS-37, ARCH-07, ARCH-22, OWT-A04, OWT-A07, OWT-A09, DATA-22 to DATA-24, API-50 and API-54. The remaining `QUALITY.md` claims hold against the code and the reports:
- every query has a LIMIT
- container limits are set
- graceful shutdown is configured
- one transaction per write
- the backup and restore round trip was run
- the load test figures match `reports/loadtest.txt`

## 4. Findings for the next run

1. **Fix decision Q4.** It still says "One backend instance (D81)", although D82 withdrew D81 and the build runs two replicas. Align Q4 with D82 and D102.
2. **Reconsider the status-code ordering decisions (D67, D139, D63).** They are why the build has its own security gate and three routing tables. Either accept the Spring Security resource server's order (401 before 405 and 406), or require one source for the operation table: generate `OperationCatalog` and the nginx map from `openapi-decided.yaml`, or test the nginx map against it.
3. **Make D98 checkable.** Add a decision line such as "bind the management server to a separate network or address (`management.server.address`)", and a smoke check that the front network cannot reach port 8081.
4. **Pipeline and lint.** Even without CI (D95), ask for a pipeline file (e.g. `.gitlab-ci.yml`) with lint, format, test and scan jobs, so OPS-37 and CODE-54 can be met. Do not skip Spotless in the image build. Add ruff for Python and shellcheck for shell. Use `jq` or Python for JSON in scripts.
5. **QUALITY.md template.** Require a row per Q target with target, measured value and verdict, or "not measured: reason" (NFR-13). Availability is the one that went missing.
6. **REUSE.md template.** Require an inventory of every own class over about 50 lines that does routing, security, parsing or infrastructure work, so completeness can be checked mechanically.
7. **API-35.** Set Accept on every outgoing call (`application/json` on the JWKS fetch, and an explicit Accept on SPARQL updates).
8. **Owner questions for the CDM.** Generic dates (DATA-12), search classes (DATA-14) and untyped attributes (DATA-10) belong to the CDM owners; add them to the open questions list.
9. **Rule hygiene.** OPS-17, SEC-02 and UX-01 cannot be judged in a factory build. Either remove them from step 70 or supply their inputs, so they stop showing up as noise.
10. **Platform-deferred MUSTs.** TLS, encryption at rest, token-failure limiting and alerting are deferred by decision. Add one production-readiness decision that names who closes each, so the deferral does not quietly become permanent.
