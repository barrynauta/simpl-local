# API notes

Base URL: `http://localhost:8196/v1` (gateway) or through the UI at `http://localhost:4433/v1`.
The wire format is the published OpenAPI (`input/specs/api/vocabulary_openapi-tier1.yaml`) with
the decided changes of D79 and later; the full decided contract is
[openapi-decided.yaml](openapi-decided.yaml), generated by `tools/make_openapi_decided.py`. The
published file is not changed (D39). `OpenApiContractTest` checks the route table, query
parameters, form fields, limits and patterns of the code against the decided file (D93).

## Operations and roles (D16)

| Operation | Role |
|---|---|
| GET /health | none |
| every other GET, POST /vocabularies/searches, POST /external-vocabulary/searches, POST /external-vocabularies/content | GA_VOCABULARY_VIEWER or GA_VOCABULARY_ADMIN |
| POST /vocabularies, POST .../versions, both PATCH, POST and DELETE /external-vocabularies | GA_VOCABULARY_ADMIN |

## Decided changes against the published contract (D79 list)

Stricter: 401 and 403 on every secured operation; pageSize at most 100; integers are int32 written
as digits only (D91, D112); name 3 to 64 characters and pattern; description and changelog 1 to
1000 characters after trimming; unknown form fields, JSON properties and query parameters 400, a
repeated query parameter 400 with one issue; a `version` form field on POST .../versions 400;
search arrays and totals (at most 100); at most 20 aliasUris, no duplicates, absolute URIs; the
file must be valid, non-empty Turtle; invalid path values 400 (not 404); 406; 405 with Allow on
undeclared methods (before 401); multipart request at most 6 MB and file part at most 5 MB (413);
JSON body at most 1 MB (413, detail 'The request body is larger than 1 MB.'); more than 64
multipart parts 400; 409 on POST .../versions for identical content and description; 503 with
Retry-After 5 when the store or the identity provider is not available.

Wider: the list name filter is a case-insensitive 'contains' with pattern `^[A-Za-z0-9]+$`;
createdBy and latestVersionHref on version objects; validationWarnings always present on the 201
of a creation; aliasUris always present; `truncated: true` on a validation report with more than
1000 issues.

## Error model (D48, D104)

Every error is `application/problem+json` (RFC 9457): `type`, `href` (Belgif types), `title`,
`status`, `detail`, `instance` (`urn:uuid:...`), `issues` when there are any.

| Status | type |
|---|---|
| 400 | urn:problem-type:belgif:badRequest (issues: `...input-validation:schemaViolation` for request shape, `...:invalidInput` for content validation) |
| 401 | urn:problem-type:simpl:unauthorized |
| 403 | urn:problem-type:simpl:forbidden |
| 404 | urn:problem-type:belgif:resourceNotFound |
| 405 | urn:problem-type:simpl:methodNotAllowed |
| 406 | urn:problem-type:simpl:notAcceptable |
| 409 | urn:problem-type:simpl:conflict |
| 413 | urn:problem-type:simpl:payloadTooLarge |
| 415 | urn:problem-type:simpl:unsupportedMediaType |
| 500 | urn:problem-type:belgif:internalServerError |
| 503 | urn:problem-type:belgif:serviceUnavailable (Retry-After: 5) |

Fixed detail texts: see D4, D15, D41, D44, D46, D47, D55, D66, D92, D147, D150 and
`ApiException`. Field messages of 400 issues are free text (D55).

## Order of checks

Writes (D51, D63): 405, 401, 403, 406, 415, 413, 400 (path, query, unknown fields, field rules,
version field), 404, 409, content validation (syntax, then semantic). Reads (D162): 405, 401, 403,
406, 400 (path and query), then the store (404 or 503).

## Paging (D22, D59, D78, D110, D111)

`page` from 1, `pageSize` 1 to 100, default 20. Links `self` and `first` always; `prev`, `next`,
`last` when they exist; beyond the last page `prev` points to the last page; `last` is left out
when total is 0. Links carry `page` and `pageSize` first, then the other parameters in request
order. Searches are not paged: page 1, pageSize 100, total, totalPages 1 (0 when empty), no links.

## Content

Downloads return the stored bytes with `Content-Type: text/turtle` (no charset) and
`Content-Disposition: attachment; filename="<Name>.ttl"` or `"<Name>-v<n>.ttl"`. Uploads are
multipart/form-data with the file in part `vocabularyFile`.

## Validation

Syntax (Jena RIOT, Turtle 1.1): one issue for the first error, location `line N, column M`,
detail starting 'Encountered invalid Turtle syntax'. Semantic: S1 to S6 of D9 and S7 (missing
internal reference), all errors in one report, in file order, at most 1000. Warnings:
`externalReferenceSkipped`, `deprecatedVocabularyReference` (texts of D47). Relative IRIs resolve
against `<contentBase>/content/<Name>/versions/<n>` (D57) or the namespace URI for external
files (D124). `contentBase` is `VOCABULARY_CONTENT_BASE_URL`, default
`https://authority.example/vocabulary-manager`.
