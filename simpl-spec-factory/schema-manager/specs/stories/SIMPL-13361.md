# SIMPL-13361: [UI] Governance Authority revoking a schema via UI
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-05-15, updated: 2026-09-28
- Source: https://jira.simplprogramme.eu/browse/SIMPL-13361 (collected 2026-10-28)

## Description and acceptance criteria

# Storycard\
|As|Governance Authority Administrator|\
|I want|to revoke a schema through the schema management UI|\
|so that|I can prevent further use of an outdated or problematic schema in the dataspace|

# Acceptance criteria\
|Scenario||The Governance Authority revokes a schema through the UI|\
**Given** I am logged into the UI of the Governance Authority with a user account that has the GA_SCHEMA_ADMIN role\
**And** the list of schemas is displayed, as well as a Revoke action button\
**When** I request to revoke the schema by clicking on "Revoke" button\
**And** I confirm the action in the popup by clicking on 'confirm' button (mockup below)\
**And** the UI calls PATCH /schemas/{schemaName} and request body {"status": "REVOKED"}\
**And** the revocation of the schema is successful\
**Then** the schema list is refreshed showing that the schema is REVOKED\
**And** the success message is displayed: "Schema "{schema_name}" revoked successfully."

## Technical details:\
|Revoke button should be available only for schemas which have status: PUBLISHED and should be hidden from the list of actions for REVOKED status|\
|The UI shows confirmation popup on Revoke button click (mockup is below)|\
|After clicking on Cancel button, the popup should be closed and revocation process should be stopped|\
|After clicking on Revoke button: UI calls SMS API revocation method and waits for the response|\
|The API endpoint for revoking a schema is PATCH /schemas/{schemaName} and request body {"status": "REVOKED"}\
Implemented in: [https://jira.simplprogramme.eu/browse/SIMPL-13360]|\
|Successful revocation returns a 200 OK response with the updated schema details|\
|The UI updates schema status on the schema list to reflect the new status of the schema|\
|Implement proper error handling for API failures or unauthorized access and use the 'detail' parameter of the response|\
|The UI should adhere to the design principles: [https://confluence.simplprogramme.eu/pages/viewpage.action?pageId=48431839]|
