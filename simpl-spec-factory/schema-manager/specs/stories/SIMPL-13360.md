# SIMPL-13360: Governance Authority – revoking a schema via API
- Status: Ready for DG Acceptance
- Type: Story
- Created: 2025-05-15, updated: 2026-09-22
- Source: https://jira.simplprogramme.eu/browse/SIMPL-13360 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority administrator,

**I want** to change the status of a schema to "REVOKED" via the API,

**So that** I can prevent any version of that schema from being used for new (versions of) resource descriptions.

## Acceptance Criteria

### Positive Scenario: Successfully revoking a schema\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role.

**And** a schema with the name {schemaName} exists and its current status is PUBLISHED.\
**When** I send a PATCH request to the /schemas/{schemaName{}} endpoint with the JSON body {"status": "REVOKED"}\
**Then** the schema status is set to REVOKED\
**And** the service shall respond with a 200 OK HTTP status.

**And** the response body shall contain the "status", confirming that it is now REVOKED.

### Negative Scenario: Schema does not exist\
**Given** I am an API client with the `GA_SCHEMA_ADMIN` role.\
**And** there is no schema with the name nonExistentSchemaName

**When** I send a PATCH request to /schemas/{nonExistentSchemaName{}}

**Then** the service shall respond with a 404 Not Found HTTP status.

### Negative Scenario: Insufficient permissions\
**Given** I am an API client with a role other than `GA_SCHEMA_ADMIN`

**When** I send a PATCH request to the /schemas/{schemaName{}} endpoint.

**Then** the service shall respond with a 403 Forbidden HTTP status.

### Negative Scenario: Invalid request body\
**Given** I am an API client with the `GA_SCHEMA_ADMIN` role.\
**When** I send a PATCH request to /schemas/{schemaName{}} with an invalid status value (e.g. {"status": "ARCHIVED"})\
**Then** the service shall respond with a 400 Bad Request HTTP status.
