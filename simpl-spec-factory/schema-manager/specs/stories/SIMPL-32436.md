# SIMPL-32436: Governance Authority – retaining revoked schema for resource descriptions for referencing via API
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2026-09-03, updated: 2026-10-16
- Source: https://jira.simplprogramme.eu/browse/SIMPL-32436 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority,\
**I want** to retain a revoked schema for Resource Descriptions,\
**So that** I can ensure that the existing resource descriptions still can reference it.

Acceptance criteria:

**Given** I am authenticated as a Governance Authority user, with a role authorising schema management and a resource description in my catalogue refers to a certain schema for resource descriptions\
**When** I revoke that schema via the UI or the API\
**Then** the reference in the published resource description is still valid and retrievable.

**Given** I am authenticated as a Governance Authority user, with a role authorising schema management\
**When** I revoke the federated search schema via the UI or the API\
**Then** the federated search across multiple trustor GA is disabled.



Technical Details:\
- ensure, that due to introduction of federated search schema retaining is only needed for schema for resource descriptions, but not for federated search schema.\
- ensure implementend functionality only covers schemas for resource descriptions, but not federated search schemas.\
- For SEARCH Schema there is no retaining functionality. According to ADR-009 there is only one federated Search Schema possible. It there is no valid federated Search Schema published no federated Search cross multiple data spaces is possible.
