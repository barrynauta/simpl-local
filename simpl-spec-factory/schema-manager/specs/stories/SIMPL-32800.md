# SIMPL-32800: [ENHANCE][UI] - Governance Authority – providing details of a new schema via a UI
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2026-09-08, updated: 2026-10-14
- Source: https://jira.simplprogramme.eu/browse/SIMPL-32800 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority administrator,

**I want** to use a web interface to define a new schema by providing its type (RESOURCE or SEARCH), its core properties and uploading its definition file,

**So that** I can ensure schemas for resource description publication and search and for federated search are available to the data space participants

Acceptance Criteria:

PATH creating a new Resource Definition Schema with Default Option\
**Given** I am logged into the schema management UI with a user account that has the `GA_SCHEMA_ADMIN` role,\
**And** I have navigated to the "Create New Schema" section of the portal.\
**Then** the schema type should be set by default to "RESOURCE" with enabled selection field for resource type\
**When** I complete the "Create Schema" form by:\
- Entering a new Schema Name (`{}name{`}, e.g., `{}DataAsset{`}).\
- Providing a human-readable Title and Description for the schema.\
- Selecting a `resourceType` from the available options (`{}data{`}, `{}infrastructure{`}, `{}application{`}).\
**And** Uploading a valid `.ttl` file containing the SHACL definition.\
**And** I submit the form,\
**Then** the UI shall call the backend `POST /schemas` endpoint on my behalf, passing the form data schemaName, schemaType, title, description and file\
**And** the UI shall provide immediate feedback, displaying a success message upon receiving a `201 Created` response from the API.\
**And** upon success, I shall be redirected to the details page for the newly created schema concept.

PATH creating initial Federated Search Schema\
**Given** I am logged into the schema management UI with a user account that has the `GA_SCHEMA_ADMIN` role,\
**And** there is no published federated search schema\
**And** I have navigated to the "Create New Schema" section of the portal.\
**Then** the schema type should be set by default to "RESOURCE" with enabled selection field for resource type\
**When** I complete the "Create Schema" form by:\
- Entering a new Schema Name (`{}name{`}, e.g., `{}DataAsset{`}).\
- Providing a human-readable Title and Description for the schema.\
- Selecting the schemaType from the available options (RESOURCE, SEARCH)\
**And** I selected schemaType "SEARCH" then the field resourceType should be disabled and I cannot select a resourceType, i.e. resoureceType=NULL,\
**And** Uploading a valid `.ttl` file containing the SHACL definition.\
**And** I submit the form,\
**Then** the UI shall call the backend `POST /schemas` endpoint on my behalf, passing the form data schemaName, schemaType, title, description and file\
**And** the UI shall provide immediate feedback, displaying a success message upon receiving a `201 Created` response from the API.\
**And** upon success, I shall be redirected to the details page for the newly created schema concept.

Negative scenario:

PATH creating a new Resource Definition Schema for already existing schema file\
**Given** I am logged into the schema management UI with a user account that has the `GA_SCHEMA_ADMIN` role,\
**And** there is already a schema file with given schema name for schema type = RESOURCE\
**And** I have navigated to the "Create New Schema" section of the portal.\
**Then** the schema type should be set by default to "RESOURCE" with enabled selection field for resource type\
**When** I complete the "Create Schema" form by:\
- Entering the given Schema Name (`{}name{`}, e.g., `{}DataAsset{`}).\
- Providing a human-readable Title and Description for the schema.\
- Selecting the schemaType = RESOURCE\
- Selecting a `resourceType` from the available options (`{}data{`}, `{}infrastructure{`}, `{}application{`}).\
- Uploading a valid `.ttl` file containing the SHACL definition.\
**And** I submit the form,\
**Then** the UI shall call the backend `POST /schemas` endpoint on my behalf, passing the form data schemaName, schemaType, title, description and file\
**Then** the API shall return an error `{}409 CONFIG{`}, the UI shall remain on the form and display a user-friendly message explaining the reason for the failure ("A schema with that name already exists.").

**And** there is already a schema file with given schema name for schema type = SEARCH\
