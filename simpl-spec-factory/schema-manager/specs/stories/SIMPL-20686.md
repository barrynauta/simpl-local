# SIMPL-20686: Automatic status assignment when creating schemas by resourceType

## Description and acceptance criteria

**As a** *Governance Authority User*,

**I want** the set the status of the schema when it's being created,

so I only have 1 PUBLISHED version of the schema of a specific resource type at the same time.\
## Acceptance Criteria: Schema Creation API Status Logic

The following criteria define the expected system behavior when a new schema is created via the API, specifically concerning the automatic assignment of the `status` field based on the presence and status of existing schemas for the same `resourceType`.\
### Positive Scenarios

**Scenario: Create first schema for a resource type**\
**Given** no schemas exist for a specific resourceType

**When** I create a new schema for that resourceType

**Then** the new schema's status must be set to PUBLISHED

**Scenario: Create new schema when a PUBLISHED one already exists**\
**Given** a schema exists for specific resourceType with status PUBLISHED

**When** I create a new schema for that resourceType

**Then** the new schema's status must be set to REVOKED

**And** the status of the existing schema remains PUBLISHED

**Scenario: Create new schema when only REVOKED schemas exist**\
**Given** multiple schemas exist for a specific resourceType

**And** all existing schemas of that resourceType have the status REVOKED

**When** I create a new schema for that resourceType

**Then** the new schema's status must be set to PUBLISHED
