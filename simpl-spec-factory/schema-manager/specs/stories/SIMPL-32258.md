# SIMPL-32258: Governance Authority - retrieving list of schemas via API [Extension]

## Description and acceptance criteria

**When** retrieving the available schemas, the schema type should be returned which can be: 'Resource description schema' or 'Federated search schema'.

**As a** Governance Authority,

**I want** to retrieve a list of all schemas available in the system via API,

**So that** I can get a high-level overview of all registered schemas.\
Acceptance Criteria:

Positive Scenario 1: without optional filter schema type (default value: schema type = RESOURCE)\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_VIEWER` or `GA_SCHEMA_ADMIN` role.\
**When** I send a `GET` request to the `/schemas` endpoint.\
**Then** the service shall respond with a 200 OK HTTP status.\
**And** the response body shall contain a paginated list of resource schema definitions (20 items / page by default, see pagination guidelines).\
**And** each resource in the list shall include all metadata.

Positive Scenario 2: with filter schema type = SEARCH\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_VIEWER` or `GA_SCHEMA_ADMIN` role.\
**When** I send a `GET` request to the `/schemas` endpoint with filter schemaType = SEARCH.\
**Then** the service shall respond with a 200 OK HTTP status.\
**And** the response body shall contain a paginated list of Federated Search schema definitions (20 items / page by default, see pagination guidelines).\
**And** each resource in the list shall include all metadata.

Positive Scenario 3: with filter on status and resource type\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_VIEWER` or `GA_SCHEMA_ADMIN` role.\
**When** I send a `GET` request to the `/schemas` endpoint with the supported query parameters\
- ** `status` (e.g., `{}GET /api/v1/schemas?status=PUBLISHED{`})\
- ** `resourceType` (e.g., `{}GET /api/v1/schemas?resourceType=data-schema{`})\
**Then** the service shall respond with a 200 OK HTTP status.\
**And** the response body shall contain a paginated list of resource schema definitions  that match the provided filter criteria and the default value schema type = RESOURCE.{}

Negative Scenario:\
**Given** I am an API client without a valid authentication token,\
**When** I send a `GET` request to the `/schemas` endpoint,\
**Then** the service shall respond with a `401 Unauthorized` HTTP status.\
**Given** I am an API client with a valid authentication token but without the required `GA_SCHEMA_VIEWER` or `GA_SCHEMA_ADMIN` role,\
**When** I send a `GET` request to the `/schemas` endpoint,\
**Then** the service shall respond with a `403 Forbidden` HTTP status.\
**Given** I am an API client with a valid authentication token,\
**When** I send a `GET` request to the `/schemas` endpoint with an invalid query parameter (e.g., `{}?status=INVALID_STATUS{`}),\
**Then** the service shall respond with a `400 Bad Request` HTTP status.\
**And** the response body should contain a problem details JSON object explaining the error.
