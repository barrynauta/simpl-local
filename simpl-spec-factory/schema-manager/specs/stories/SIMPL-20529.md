# SIMPL-20529: [API] Governance Authority -  change the status of a schema via API
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-11-10, updated: 2026-09-22
- Source: https://jira.simplprogramme.eu/browse/SIMPL-20529 (collected 2026-10-28)

## Description and acceptance criteria

Storycard:\
|As|a Governance Authority user with a role allowing schema management|\
|I want|to change the status of a validated schema to REVOKED or to PUBLISHED VIA an API|\
|so that|the schema can be used (PUBLISHED) or can not be used (REVOKED) for publication of new resource descriptions|

Acceptance criteria:\
|Scenario|The Governance Authority changes the state of a schema to PUBLISHED via API|\
**Given** I am a Governance Authority user with a valid authentication token granting the `GA_SCHEMA_ADMIN` role\
**And** schema status is REVOKED\
**And** all schemas of the same resource type are in state REVOKED\
**When** I send a `PATCH` request to publish a schema: PATCH /schemas/{schemaName} and Request Body: {"status": "PUBLISHED"}\
**And** the status of the schema updated to "PUBLISHED"\
**Then** the service return shall return with 200 OK\
**And** the response body shall contain the name and the status of the schema

|Scenario|The Governance Authority changes the state of a schema to REVOKED via API|\
**Given** I am a Governance Authority user with a valid authentication token granting the `GA_SCHEMA_ADMIN` role\
**And** schema status is PUBLISHED\
**When** I send a `PATCH` request to publish a schema: PATCH /schemas/{schemaName} and Request Body: {"status": "REVOKED"}\
**And** the status of the schema updated to "REVOKED"\
**Then** the service return shall return with 200 OK\
**And** the response body shall contain the name and the status of the schema

Negative scenarios:

**Given** I am a Governance Authority user with the `GA_SCHEMA_ADMIN` role

**When** I send a `PATCH` request where the `status` value is neither `REVOKED` nor `PUBLISHED`

**Then** the service shall respond with `400 Bad Request` and a Problem Details JSON.

*---

**Given** I am a user without the `GA_SCHEMA_ADMIN` role

**When** I send a `PATCH` request to change a schema status

**Then** the service shall respond with `403 Forbidden`.

*---

**Given** I am a Governance Authority user with the `GA_SCHEMA_ADMIN` role

**When** I send a `PATCH` request for a `schemaName` that does not exist

**Then** the service shall respond with `404 Resource Not Found`.

—

**Given** I am a Governance Authority user with the `GA_SCHEMA_ADMIN` role

**When** I send a `PATCH` request with an `Accept` header other than `application/json` or `application/problem+json`

**Then** the service shall respond with `406 Not Acceptable`.

—

**Given** I am a Governance Authority user with the `GA_SCHEMA_ADMIN` role

**When** I request a status change to a state the schema is already in

**Then** the service shall respond with `409 Conflict`.

—-

**Given** a schema is in state `REVOKED`

**And** another schema of the same `resourceType` is already in state `PUBLISHED`

**When** I request to change the `REVOKED` schema to `PUBLISHED`

**Then** the service shall respond with `409 Conflict` explaining that only one schema per resource type can be published.

—-

**Given** a server-side error occurs during processing

**When** I send a valid `PATCH` request

**Then** the service shall respond with `500 Internal Server Error` and no changes shall be persisted.

–--

Technical details:\
|Limitation: ONLY 1 SCHEMA / RESOURCE TYPE CAN BE PUBLISHED AT THE SAME TIME|\
|After successful update API returns `200 OK`: and the full, updated resource representation of the schema concept|\
