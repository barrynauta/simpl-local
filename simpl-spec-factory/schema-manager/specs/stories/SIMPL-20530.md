# SIMPL-20530: [UI] Governance Authority changes the status of a schema via UI
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-11-10, updated: 2026-09-28
- Source: https://jira.simplprogramme.eu/browse/SIMPL-20530 (collected 2026-10-28)

## Description and acceptance criteria

Storycard:\
|As|Governance Authority user authorised to manage schemas|\
|I want|to change the status of a validated schema to REVOKED or to PUBLISHED via UI|\
|so that|the schema can be used (PUBLISHED) or can not be used (REVOKED) for publication of new resource descriptions|

Acceptance criteria:\
|Scenario|The Governance Authority changes the status of a schema to REVOKED via the UI|\
**Given** I am logged into the UI of the Governance Authority with a user account that has the GA_SCHEMA_ADMIN role\
**And** the list of schemas is displayed\
**And** a schema status is PUBLISHED with an action button 'Revoke'\
**When** I click on 'Revoke' button\
**And** the UI calls PATCH method implemented in [https://jira.simplprogramme.eu/browse/SIMPL-20529] with REVOKED state in the body\
**And** the call is successful\
**Then** Success notification message shows: "Schema state changed."\
**And** "Status" is updated to REVOKED in the schema list

|Scenario|The Governance Authority changes the status of a schema to PUBLISHED via the UI|\
**Given** I am logged into the UI of the Governance Authority with a user account that has the GA_SCHEMA_ADMIN role\
**And** the list of schemas is displayed\
**And** a schema status is REVOKED with an action button 'Publish'\
**And** no other schema is in PUBLISHED state for the same resource type\
**When** I click on 'Publish' button\
**And** the UI calls PATCH method implemented in [https://jira.simplprogramme.eu/browse/SIMPL-20529] with PUBLISH state in the body\
**And** the call is successful\
**Then** Success notification message shows: "Schema state changed."\
**And** "Status" is updated to REVOKED in the schema list

Negative scenario:\
**Given** I am logged into the UI of the Governance Authority with a user account that has the GA_SCHEMA_ADMIN role\
**And** the list of schemas is displayed\
**And** a schema status is REVOKED with an action button 'Publish'\
**And** another schema is in PUBLISHED state for the same resource type\
**When** I click on 'Publish' button\
**And** the UI calls PATCH method implemented in [https://jira.simplprogramme.eu/browse/SIMPL-20529] with PUBLISH state in the body\
**And** the response is '409 Conflict' HTTP status\
**Then** Error notification showing: "Another schema is in PUBLISHED state for the resource type."\
**And** "Status" is not updated to REVOKED in the schema list

**Given** I am logged into the UI of the Governance Authority with a user account that has the GA_SCHEMA_ADMIN role\
**And** the list of schemas is displayed\
**And** a schema status is REVOKED with an action button 'Publish'\
**And** no other schema is in PUBLISHED state for the same resource type\
**When** I click on 'Publish' button\
**And** the UI calls PATCH method implemented in [https://jira.simplprogramme.eu/browse/SIMPL-20529] with PUBLISH state in the body\
**And** the call returns with an error (e.g., Bad Request or 404 Not found)\
**Then** the UI shall remain on the form and display a user-friendly message explaining the reason for the failure\
**And** "Status" remains REVOKED in the schema list

Technical details:\
|The UI should integrate with the Schema Management Service (SMS) API|\
|The UI shows "Publish" button in the action list only for schemas which are in REVOKED status|\
|The UI shows "Revoke" button in the action list only for schemas which are in PUBLISHED status|\
|API definition task: [https://jira.simplprogramme.eu/browse/SIMPL-16762]|\
|After clicking on "Publish" button the UI should call PATCH method implemented in [https://jira.simplprogramme.eu/browse/SIMPL-20529]|\
|Only users with GA_SCHEMA_ADMIN can perform this action|\
|The UI updates schema list to status PUBLISHED in the "Status" column and show notification message: "Schema {schema_name} published successfully!"|\
|Implement proper error handling for API failures or unauthorized access with error messages|\
|The UI should adhere to the design principles: [https://confluence.simplprogramme.eu/pages/viewpage.action?pageId=48431839]|\
|Note: a new version does not have its own status - it inherits the status of the schema concept|
