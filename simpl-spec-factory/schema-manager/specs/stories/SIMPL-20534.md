# SIMPL-20534: Governance Authority automatically assigning the next version number, based on the applicable versioning algorithm
- Status: Ready for DG Acceptance
- Type: Story
- Created: 2025-11-11, updated: 2026-09-22
- Source: https://jira.simplprogramme.eu/browse/SIMPL-20534 (collected 2026-10-28)

## Description and acceptance criteria

# Storycard:\
||As|Governance Authority|\
||I want|Simpl to automatically assign the next version number, based on the applicable versioning algorithm, when creating a new schema version number|\
||so that|I can identify each schema version uniquely ensuring traceability|

# Acceptance criteria:\
||Scenario||The Governance Authority creates new schema version||\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role\
**When** I send a `POST` request with a a valid schema to the `/schemas/{schemaName}/versions` without version number parameter\
**Then** Simpl assigns the next version number, based on the applicable versioning algorithm for the new schema version

## Negative scenario\
||Scenario||The Governance Authority’s attempt to create a new schema version fails because the automatic version number could not be assigned||\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role\
**When** I send a `POST` request with a a valid schema to the `/schemas/{schemaName}/versions` endpoint without version number parameter\
**And** Simpl fails to assign the next version number, based on the applicable versioning algorithm for the new schema version\
**Then** the service shall respond with a `500 Internal Server Error` Status

# Technical details:\
|Schema versioning should be a number in the format, starting from 1 (e.g: 1, 2, 3, etc)|\
|Schema version should be defined on API and be incremented every time when schema version is added|\
|The biggest version number should relate to the latest schema version|\
|Schema Version number parameter should be removed from POST `/schemas/{schemaName}/versions` endpoint parameters|

API definition ticket: [https://jira.simplprogramme.eu/browse/SIMPL-12816]

# IMPORTANT!\
* we need to implement a library to handle versioning - interface should be something of sorts

```java\
interface VersioningContext {\
// 1. The previous version identifier (Required)\
currentVersion: string;

// 2. The semantic severity of the change (Required for SemVer)\
changeType?: 'PATCH' | 'MINOR' | 'MAJOR';

// 3. Optional: The actual asset metadata/content (For advanced logic)\
// This allows the library to auto-detect changes (e.g., hashing the schema).\
currentItem?: ItemMetadata+Data (for schema, resource descriptions etc.);\
newItem?: ItemMetadata+Data (for schema, resource descriptions etc.);\
}

interface VersionResult {\
version: string;          // e.g., "1.2.0"\
}\
```
