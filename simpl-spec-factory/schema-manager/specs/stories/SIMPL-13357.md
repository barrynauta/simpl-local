# SIMPL-13357: Governance Authority – providing details of a new version of an existing schema via API
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-05-15, updated: 2026-09-22
- Source: https://jira.simplprogramme.eu/browse/SIMPL-13357 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority administrator,\
**I want** to submit a new version of an existing schema by providing a version number, changelog, and a new definition file via the API,\
**So that** I can update a schema with new properties or constraints while maintaining a full version history.

## Acceptance Criteria:

### Positive Scenario\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role,

**And** a schema with the name `{schemaName}` already exists,\
**And** the latest version of that schema can be uniquely identified by its status PUBLISHED\
**When** I send a `POST` request to the `/schemas/{schemaName}/versions` endpoint with a `multipart/form-data` body containing:\
- A `metadata` part with a new, unique, and valid SemVer `version` (e.g., "1.1.0") and a `changelog` description.\
- A `file` part containing a valid SHACL definition in a `.ttl` file.\
**Then** the new schema version is stored with the provided metadata and SCHACL definition\
**And** the new schema version has status PUBLISHED\
**And** the status of the previous version (was the latest before) has changed from PUBLISHED to REVOKED

**And** the service responds with a `201 Created` HTTP status.

**And** the response `Location` header contains the URI for the newly created schema version.

**And** the response body contains the full resource metadata representation of the new version.

### Negative Scenarios\
**Given** I am an API client with a valid authentication token,\
**And** the schema with name `{nonExistantSchemaName}` doesn't exist\
**When** I send a `POST` request to `/schemas/{nonExistentSchemaName}/versions`,

**Then** the service shall respond with a `404 Not Found` HTTP status.

—\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role,\
**And** a schema with the name `{schemaName}` already exists,\
**And** a version number of it: `{schemaVersion}` that already exists\
**When** I send a `POST` request to `/schemas/{schemaName}/versions` with version number `{schemaVersion}`,

**Then** the service shall respond with a `409 Conflict` HTTP status,\
**And** the response body shall contain a problem details JSON object explaining the version conflict.

—\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role,\
**And** I have an invalid SHACL file\
**And** correct metadata (e.g. version, schemaName)\
**When** I send a `POST` request to `/schemas/{schemaName}/versions` with said file

**Then** the service shall respond with a `400 Bad Request` HTTP status,\
**And** the response body shall contain a problem details JSON object explaining the validation error.

-\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role,\
**And** I have a valid SHACL file\
**And** malformed metadata (e.g., invalid version format, missing changelog),\
**When** I send a `POST` request to `/schemas/{schemaName}/versions` with said SHACL file and metadata

**Then** the service shall respond with a `400 Bad Request` HTTP status,\
**And** the response body shall contain a problem details JSON object explaining the validation error.

-\
**Given** I am an authenticated API client\
**When** an unexpected server-side error occurs while processing the request\
**Then** the system must return Internal Server Error\
**And** the service shall respond with a `500 Error` HTTP Status
