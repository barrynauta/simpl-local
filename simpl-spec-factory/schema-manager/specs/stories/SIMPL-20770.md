# SIMPL-20770: [UI] Remove version number field from Create Schema Version screen
- Status: DevTeam PBI is ready for Implementation check
- Type: Story
- Created: 2025-11-14, updated: 2026-09-25
- Source: https://jira.simplprogramme.eu/browse/SIMPL-20770 (collected 2026-10-28)

## Description and acceptance criteria

# Storycard:\
|As|Governance Authority|\
|I want|Simpl to automatically assign the next version number, based on the applicable versioning algorithm|\
|so that|I can create a new schema version via UI without entering the version number|

# Acceptance criteria:\
|Scenario|The Governance Authority creates new schema version|\
**Given** I am logged in as a user into the governance management UI that has the GA_SCHEMA_ADMIN role\
**And** I navigate to the action button of a schema\
**When** I initiate the "Create New Version" action (e.g., by clicking a New Version button).\
**Then** the UI to create a new schema version is displayed\
**And** the UI does not include a field for providing the version number

|Scenario|The Governance Authority creates new schema version|\
**Given** I am logged in as a user into the governance management UI that has the GA_SCHEMA_ADMIN role\
**And** I navigate to the action button of a schema\
**When** I initiate the "Create New Version" action (e.g., by clicking a New Version button).\
**And** I fill in all required fields in the form, without a version number field\
**And** I upload a valid schema definition file (e.g., a .ttl file)\
**And** I submit the form\
**Then** the UI shall send a POST request to the /schemas/{schemaName}/versions endpoint with the form data as multipart/form-data excluding version number parameter\
**And** Simpl automatically assign the next version number, based on the applicable versioning algorithm\
**And** API shall respond with a 201 Created HTTP status\
**And** I should be redirected back to the list of schema's page, where the newly created version is now visible in the version list

## Negative scenario:\
**Given** I am logged in as a user into the governance management UI that has the GA_SCHEMA_ADMIN role\
**And** I navigate to the action button of schema\
**When** I initiate the "Create New Version" action (e.g., by clicking a New Version button).\
**And** I fill in all required fields in the form, without a version number field, which should be removed from UI\
**And** I upload a valid schema definition file (e.g., a .ttl file)\
**And** I submit the form\
**Then** the UI shall send a POST request to the /schemas/{schemaName}/versions endpoint with the form data as multipart/form-data excluding version number parameter\
**And** API returns an error\
**And** Then the UI remains on the list of schema's page and displays an error message explaining the failure (e.g., showing the details field content of the response")

# Technical details:\
|Schema version number input field should be removed from the form for New Schema Version creation|\
|Schema version number should be removed from API POST call|\
|SMS API should automatically increase version number of the schema by 1|
