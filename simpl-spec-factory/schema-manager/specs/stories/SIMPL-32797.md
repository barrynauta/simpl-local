# SIMPL-32797: [ENHANCE][UI] - Governance Authority - retrieving details of a schema version via a UI
- Status: FOR SC TO RESPOND
- Type: Story
- Created: 2026-09-08, updated: 2026-10-20

## Description and acceptance criteria

**As a** Governance Authority User,

**I want** to download the file for any schema version from schema versions list page in the UI,

**So that** I can inspect its contents offline or use it in my local tools.

Acceptance Criteria:\
**Given** I am an authenticated Governance Authority user with a `GA_SCHEMA_VIEWER` or `GA_SCHEMA_ADMIN` role\
**And** I view the schema versions list page,\
**And** a specific version of a schema (e.g. 1),\
**And** specify schemaType (default value is RESOURCE)\
**And** download action is available for this version of the schema,\
**When** I request to download the content of this specific version of the schema,\
**Then** my browser downloads the file of the specific schema definition (e.g. 1)\
**And** Simpl provides a success message on the schema versions list page.

Negative scenario:\
**Given** I am an authenticated Governance Authority user with a `GA_SCHEMA_VIEWER` or `GA_SCHEMA_ADMIN` role\
**And** I view the schema versions list page,\
**And** a specific version of a schema (e.g. 1),\
**And** specify schemaType (default value is RESOURCE)\
**And** download action is available for this version of the schema,\
**And** I request to download the content of this specific version of the schema,\
**When** an error occurs during the download of the schema file,\
**Then** Simpl provides an error message on the schema versions list page.

The relevant API implementation with authorization and authentication scenario can be found here:

- BE endpoint is /schemas/{schemaName}/versions with optional filter schemaType, e.g.\
GET /schemas/{schemaName}/versions?schemaType="RESOURCE"\
- add a new entry field (selection box) for schemaType with two possible options (RESOURCE or SEARCH). RESOURCE should be the default value.\
- enhance existing solution by adding new attribute schematype to distinguish RESOURCE for already implemented solution and "SEARCH" for Federated Search schemas. Ensure by explicitely setting filter for schemaType = RESOURCE for existing test cases they still work.\
