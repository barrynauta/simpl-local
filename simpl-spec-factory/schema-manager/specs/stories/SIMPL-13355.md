# SIMPL-13355: Governance Authority – providing details of a new schema via a UI
- Status: Ready for DG Acceptance
- Type: Story
- Created: 2025-05-15, updated: 2026-10-14
- Source: https://jira.simplprogramme.eu/browse/SIMPL-13355 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority administrator,

**I want** to use a web interface to define a new schema by providing its core properties and uploading its definition file,

**So that** I can easily create and register a new schema, with the system automatically setting its initial version to "1.0.0".

Acceptance Criteria:\
**Given** I am logged into the governance management portal with a user account that has the `GA_SCHEMA_ADMIN` role,

**And** I have navigated to the "Create New Schema" section of the portal.

**When** I complete the "Create Schema" form by:\
- Entering a new Schema Name (`name`, e.g., `DataAsset`).\
- Providing a human-readable Title and Description for the schema.\
- Selecting a `resourceType` from the available options (`data`, `infrastructure`, `application`).\
- Uploading a valid `.ttl` file containing the SHACL definition.

**And** I submit the form,

**Then** the UI shall call the backend `POST /schemas` endpoint on my behalf, passing the form data appropriately.

**And** the UI shall provide immediate feedback, displaying a success message upon receiving a `201 Created` response from the API.\
**And** upon success, I shall be redirected to the details page for the newly created schema concept.

Negative scenario:

**Given** I am logged into the governance management portal with a user account that has the `GA_SCHEMA_ADMIN` role,

**And** I have navigated to the "Create New Schema" section of the portal.

**When** I complete the "Create Schema" form by:\
- Entering a new Schema Name (`name`, e.g., `DataAsset`).\
- Providing a human-readable Title and Description for the schema.\
- Selecting a `resourceType` from the available options (`data`, `infrastructure`, `application`).\
- Uploading a valid `.ttl` file containing the SHACL definition.

**And** I submit the form,

**Then** the UI shall call the backend `POST /schemas` endpoint on my behalf, passing the form data appropriately.\
- If the API returns an error (e.g., `400 Bad Request` or `409 Conflict`), the UI shall remain on the form and display a user-friendly message explaining the reason for the failure (e.g., "The uploaded file contains invalid SHACL." or "A schema with that name already exists.").
