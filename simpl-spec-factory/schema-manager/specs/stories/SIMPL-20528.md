# SIMPL-20528: Governance Authority automatically assigning an initial version number to new schema based on the applicable versioning algorithm
- Status: Ready for DG Acceptance
- Type: Story
- Created: 2025-11-10, updated: 2026-09-22
- Source: https://jira.simplprogramme.eu/browse/SIMPL-20528 (collected 2026-10-28)

## Description and acceptance criteria

# Storycard:\
||As|Governance Authority|\
||I want|Simpl to automatically assign the initial version number, based on the applicable versioning algorithm, when creating a new schema|\
||so that|I could identify each schema version uniquely ensuring traceability|

# Acceptance criteria:\
||Scenario||The Governance Authority creates a new schema for given resource type||\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role\
**When** I send a `POST` request with a valid new schema to the POST /schemas endpoint without version number parameter\
**Then** Simpl assigns the initial version number, based on the applicable versioning algorithm for the new schema

## Negative scenario:\
||Scenario||The Governance Authority’s attempt to create a new schema fails because the initial version number could not be assigned||\
**Given** I am an API client with a valid authentication token granting the `GA_SCHEMA_ADMIN` role\
**When** I send a `POST` request with a valid schema to the POST /schemas endpoint without version number parameter\
**And** Simpl fails to assign the initial version number, based on the applicable versioning algorithm for the new schema\
**Then** the service shall respond with a `500 Internal Server Error` Status

# Technical details:\
|Schema versioning should be a number in the format, starting from 1 (e.g: 1, 2, 3, etc)|\
|Schema version should be defined on API and be incremented every time a new schema version is added|\
|The biggest version number should relate to the latest schema version|
