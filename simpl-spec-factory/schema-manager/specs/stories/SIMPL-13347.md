# SIMPL-13347: Governance Authority - retrieving the contents of the latest version of a schema via API
- Status: Ready for DG Acceptance
- Type: Story
- Created: 2025-05-15, updated: 2026-09-22
- Source: https://jira.simplprogramme.eu/browse/SIMPL-13347 (collected 2026-10-28)

## Description and acceptance criteria

**As a** : User

**I want** to: Retrieve the raw SHACL content of the latest published version of a schema by making a request to a stable, public, unversioned URI

### Acceptance Criteria:\
**Given** I am an authenticated GA user,\
**And** a schema concept (e.g., ApplicationAsset) exists in the system.\
**And** the ApplicationAsset schema has a version (e.g., "1.0.0", "1.1.0", "1.2.0"), with "1.2.0" being the latest.\
**When** I send a GET request to the endpoint for the schema concept, for example, [https://api.simpl.space/schemas/ApplicationAsset].\
**Then** the service shall identify "1.2.0" as the latest version.\
**And** the service shall respond directly with a 200 OK HTTP status.\
**And** the response shall include a Content-Location header that specifies the versioned URI of the content being served (e.g., Content-Location: [https://api.simpl.space/schemas/ApplicationAsset/1.2.0]), which is also the named graph of the schema.\
**And** the response shall have a Content-Type header of text/turtle.\
**And** the body of the response shall contain the complete, raw SHACL content of version "1.2.0".

### Negative Scenarios:\
**Given** I am an authenticated GA client,\
**When** I send a GET request to the Resolver Interface endpoint for a schema name that does not exist, such as [https://api.simpl.space/schemas/NonExistentSchema].\
**Then** the service shall respond with a 404 Not Found HTTP status.

Notes:

As this is not a REST API we don't need an API Definition task for it:\
- we don't need versioning (it's the schemas that are versioned)\
- we don't need any custom headers or request params that would involve having a REST API
