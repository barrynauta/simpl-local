# SIMPL-32801: [ENHANCE] - Automatic status assignment when creating schemas by resourceType
- Status: PBI INTERNAL QA
- Type: Story
- Created: 2026-09-08, updated: 2026-10-27
- Source: https://jira.simplprogramme.eu/browse/SIMPL-32801 (collected 2026-10-28)

## Description and acceptance criteria

**As a** *Governance Authority User*,

**I want** the set the status of the schema when it's being created,

so I only have 1 PUBLISHED version of the schema of a specific resource type at the same time for schema type = RESOURCE and only one published version for schema type = SEARCH for all resource types.

## Acceptance Criteria: Schema Creation API Status Logic

The following criteria define the expected system behavior when a new schema is created via the API, specifically concerning the automatic assignment of the `status` field based on the presence and status of existing schemas for the same `resourceType and schema type`.

### Positive Scenarios

**Scenario: Create first schema for a resource type and schemaType="RESOURCE"**\
**Given** no schemas exist for a specific resourceType and schemaType="RESOURCE"

**When** I create a new schema for that resourceType and schemaType

**Then** the new schema's status must be set to PUBLISHED

**Scenario: Create new schema for schemaType="RESOURCE" when a PUBLISHED one already exists**\
**Given** a schema exists for specific resourceType and schemaType="RESOURCE" with status PUBLISHED

**When** I create a new schema for that resourceType and schemaType

**Then** the new schema's status must be set to REVOKED

**And** the status of the existing schema remains PUBLISHED

**Scenario: Create new schema and schemaType="RESOURCE" when only REVOKED schemas exist**\
**Given** multiple schemas exist for a specific resourceType and schemaType="RESOURCE"

**And** all existing schemas of that resourceType and schemaType have the status REVOKED

**When** I create a new schema for that resourceType and schemaType\
**Then** the new schema's status must be set to PUBLISHED

**Scenario: Create first schema for schemaType="SEARCH"**\
**Given** no schemas exist for schemaType="SEARCH"

**When** I create a new schema with schemaType="SEARCH"

**Then** the new schema's status must be set to PUBLISHED

**Scenario: Create new schema for schemaType="SEARCH" when only REVOKED schema exist**\
**Given** multiple schemas exist for schemaType="SEARCH"\
**And** all existing schemas have the status REVOKED

**When** I create a new schema with schemaType="SEARCH"

**Then** the new schema's status must be set to PUBLISHED

negative scenario:

**Scenario: Create a new schema with schemaType="SEARCH" when there is already a published federated search schema**\
**Given** a schema exist for schemaType="SEARCH"

**When** I create a new schema with schemaType="SEARCH", but different schemaName

**Then** Simpl shall submit an error with 409, there is already a federated search schema

NOTE:\
* According to ADR-009 only one schema of schemaType="SEARCH" for each resourceType exists in contrast to schemaType="RESOURCE", i.e. when schema type = SEARCH the value for resource type should be empty.\
* the uniqueness key is one published SEARCH schema globally, regardless of name; state that revoked schemas remain addressable as history, and define whether a new schema may reuse a revoked schema's name.\
* enhance existing solution by adding new attribute schematype to distinguish RESOURCE for already implemented solution and "SEARCH" for Federated Search schemas. Ensure by explicitely setting filter for schemaType = RESOURCE for existing test cases they still work.\
