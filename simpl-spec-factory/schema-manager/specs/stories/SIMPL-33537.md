# SIMPL-33537: [API Implementation] - API to manage federated Search Schema
- Status: DevTeam PBI In Progress
- Type: Story
- Created: 2026-09-17, updated: 2026-10-27
- Source: https://jira.simplprogramme.eu/browse/SIMPL-33537 (collected 2026-10-28)

## Description and acceptance criteria

**As a** Governance Authority\
**I want** the Schema Manager to manage Federated Search schemas\
**So that** I can enable federated search across data spaces using a validated common schema without disrupting existing resource-schema clients.

# Implementation scope

Implement the Schema Management API contract defined in [SIMPL-30422](https://jira.simplprogramme.eu/browse/SIMPL-30422). Extend the existing Schema Management API to support Resource Description schemas and Federated Search schemas through the `schemaType` attribute.\
* Support `RESOURCE` and `SEARCH` as schema types across the Schema Management API.\
* Default an omitted `schemaType` to `RESOURCE` on every Schema Management API operation, preserving the existing API behavior for current clients.\
* Return `schemaType` in schema and schema-version metadata, including list responses.\
* Support `schemaType` as an optional query filter on `GET /schemas`, `GET /schemas/{schemaName}`, `GET /schemas/{schemaName}/{version}`, and `GET /schemas/{schemaName}/versions`.\
**When** a `schemaType` filter is supplied, return only schemas or versions that match the requested `RESOURCE` or `SEARCH` type. When it is omitted from a retrieval request, return only `RESOURCE` schemas and versions.\
* Allow `schemaType` filtering to be combined with the supported `status` filter on `GET /schemas`. SEARCH schemas have no `resourceType` because they apply to all resource types; reject requests that supply `resourceType` for a SEARCH schema with `400 Bad Request`.\
* Create and version Federated Search schemas, with server-generated version numbers.\
* Allow at most one published Federated Search schema. A revoked Federated Search schema does not count as published.\
* Validate submitted Federated Search SHACL content and the default properties applicable to `SEARCH` before creation or versioning. Validation failures must prevent creation.\
* A revoked `SEARCH` schema must not be available for federated search.\
* Keep existing clients and test cases backward compatible: requests that omit `schemaType` continue to use `RESOURCE` schemas and versions.

# Acceptance criteria

## AC1: Create and validate a Federated Search schema

**Given** I am authenticated as a Governance Authority user with a role authorising schema management\
**And** there is no published (not revoked) Federated Search schema\
**When** I create a new Federated Search schema or a new version of it with `schemaType=SEARCH`\
**And** Simpl-Open successfully validates the submitted schema according to the rules and default properties for `SEARCH`\
**Then** Simpl-Open generates the version number using the versioning algorithm\
**And** Simpl-Open publish the schema or schema version

## AC2: Publish a Federated Search schema

**Given** I am authenticated as a Governance Authority user with a role authorising schema management\
**And** there is already a published Federated Search schema\
**When** I create a new Federated Search schema\
**Then** Simpl-Open rejects the attempt with `409 Conflict`.

## AC3: Filter the schema list by schema type

**Given** I am authenticated as a Governance Authority user with a role authorising schema viewing\
**When** I retrieve schemas through `GET /schemas` with `schemaType=SEARCH`\
**Then** Simpl returns only the schemas that match the requested schema type\
**And** each returned schema includes its `schemaType`.\
**And** if the request also includes `resourceType`, Simpl returns `400 Bad Request`.

## AC4: Filter Federated Search schema content and versions by schema type

**Given** I am authenticated as a Governance Authority user with a role authorising schema viewing\
**When** I retrieve a Federated Search schema's latest content, a specific schema version, or all versions of a schema with `schemaType=SEARCH`\
**Then** Simpl returns only the matching schema or schema versions\
**And** the latest-version and version-specific endpoints return the complete raw SHACL content for the matching schema version.

## AC5: Revoke a Federated Search schema

**Given** I am authenticated as a Governance Authority user with a role authorising schema management\
**When** I revoke the published Federated Search schema\
**Then** the GET endpoint on the respective federated schema shows that the schema is revoked.\
**And** after revocation, a valid Federated Search schema can be published.
