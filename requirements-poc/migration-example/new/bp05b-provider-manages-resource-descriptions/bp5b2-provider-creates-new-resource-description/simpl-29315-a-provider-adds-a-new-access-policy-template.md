# Epic: A Provider adds a new access policy template

An Epic is a feature that can be tested as a whole. This one delivers part of detailed requirement [5B.2.4 A Provider assigns access policies to a new Resource description](../bp5b2-provider-creates-new-resource-description.md#5b24-a-provider-assigns-access-policies-to-a-new-resource-description), under high-level requirement [5B.2 A Provider creates a new Resource description](../bp5b2-provider-creates-new-resource-description.md). In the process it belongs to step [BP05B.03 Add policy and contract related metadata](../README.md#bp05b03-add-policy-and-contract-related-metadata).

In the backlog (Jira) it is item SIMPL-29315. It has no user stories yet.

## What this Epic delivers

**As a** Provider\
**I want to** add a new access policy template\
**So that** I can use that when I assign an access policy in a resource description.

**Acceptance Criterion: Create a new access policy template through configuration**

The Provider can define a new access policy template through configuration. Simpl-Open will support the Provider by providing documentation and an example on

- how to create a new access policy template for contracting and consumption
- how to create an extension for the connector
- how to register the extension to the connector and bind it to that policy template
