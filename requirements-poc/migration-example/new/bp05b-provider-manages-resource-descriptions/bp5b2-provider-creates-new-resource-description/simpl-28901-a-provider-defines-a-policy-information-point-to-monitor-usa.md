# Epic: A Provider defines a policy information point to monitor usage policies

An Epic is a feature that can be tested as a whole. This one delivers part of detailed requirement [5B.2.5 A Provider assigns usage policies to a new Resource description](../bp5b2-provider-creates-new-resource-description.md#5b25-a-provider-assigns-usage-policies-to-a-new-resource-description), under high-level requirement [5B.2 A Provider creates a new Resource description](../bp5b2-provider-creates-new-resource-description.md). In the process it belongs to step [BP05B.03 Add policy and contract related metadata](../README.md#bp05b03-add-policy-and-contract-related-metadata).

In the backlog (Jira) it is item SIMPL-28901. It has no user stories yet.

## What this Epic delivers

**As a** Provider\
**I want to** define a policy information point based on the consumption logs of my resources\
**So that** I can include the policy information point in the usage policy

**and** assess whether the Consumer of my resource follows the usage policy by evaluating the policy constraints using the policy information point

**Acceptance criteria:**

The Provider can define endpoints that use aggregations of consumption logs to track the Consumer's use of a resource related to the usage policy constraints. Simpl-Open will support the Participant by providing documentation on how to create such endpoints.
