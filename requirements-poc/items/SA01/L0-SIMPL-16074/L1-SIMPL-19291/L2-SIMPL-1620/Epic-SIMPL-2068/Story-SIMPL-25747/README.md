# SIMPL-25747: Participant captures lineage within workflows

**User story (implementable work)** · Status **DevTeam PBI is ready for Implementation check**

**Trace:** [SA01](../../../../../README.md) › [SIMPL-16074](../../../../README.md) (L0) › [SIMPL-19291](../../../README.md) (L1) › [SIMPL-1620](../../README.md) (L2) › [SIMPL-2068](../README.md) (Epic) › **SIMPL-25747** (User story)

## Text

**As a** Data Provider or Consumer,\
**I want to** generate lineage on successful orchestration runs,\
**So that** processed datasets retain machine-readable provenance.

###### Technical Details:

- A run status sensor is registered for DagsterRunStatus.SUCCESS.
- The sensor monitors data_profiling_with_lineage_job.
- Sensor behavior is skip-first for missing/invalid lineage prerequisites.
- Services are extracted from run_config.ops and become prov:Activity nodes.
- Service label fallback order is lineage_activity_label, then op name.
- Missing or invalid required environment variables (LINEAGE_PARTICIPANT_NAME, URI_PREFIX) produce deterministic skips.
- Failed and cancelled runs are not in scope because the sensor is success-triggered only.
- Testing on S3

##### Acceptance Criteria

###### **AC1**

1. **Given** a workflow with -a lineage tracking flag and- a valid lineage configuration\
   **When** this workflow is run and ends successfully\
   **Then** the lineage sensor is triggered\
   **And** lineage metadata is collected from the run context and configuration\
   **And** the resulting graph is associated with that run

###### **AC2**

2. **Given** a workflow with -a lineage tracking flag and- a invalid lineage configuration\
   **When** this workflow is run and ends successfully\
   **Then** report generation is skipped\
   **And** no lineage artifact is written

###### **AC3**

3. **Given** a workflow with -a lineage tracking flag and- missing lineage env vars, or invalid URIs\
   **When** this workflow is run and ends successfully\
   **Then** report generation is skipped\
   **And** no lineage artifact is written

###### **AC4**

4. **Given** a workflow with -a lineage tracking flag and- a valid lineage configuration\
   **And** without used_input values\
   **When** this workflow is run and ends successfully\
   **Then** the lineage sensor is triggered\
   **And** lineage metadata is collected from the run context and configuration\
   **And** the resulting graph is associated with that run\
   **And** the report remains valid without prov:used entries

###### **AC5**

5. **Given** a workflow with -a lineage tracking flag- a valid lineage configuration\
   **When** this workflow is run and does not end successfully\
   **Then** the success-only lineage sensor is not triggered\
   **And** no lineage report is generated by that sensor
